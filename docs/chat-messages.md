# 会话消息修改、删除与失败后发送

## 失败后发送

输入框只在消息提交待确认、任务正在运行或排队、消息删除待确认时锁定。`paused`、`waiting_client`、`needs_review` 不会永久阻止输入；用户可以主动继续旧任务，也可以直接发送新消息。

发送新消息前，后端重新读取持久任务状态，并通过数据库条件更新结束旧的暂停任务。只有没有执行租约的暂停任务能被结束；如果旧任务已被其他连接恢复执行，新消息会被拒绝，避免两个任务同时写入。已完成或结果不确定的工具记录保留，新的上下文提醒模型先核对已有操作。

前端不会自动重发未经确认的消息。连接中断后先恢复会话，用户检查实际结果后再决定是否发送。

## 修改与新分支

生成结束后，用户消息提供修改按钮，将原文本、附件和所选应用放回输入框。点击发送使用 `message.resend`，包含原消息 ID 和会话版本号。

后端创建新的会话 ID，只复制被修改问题之前的完整问答，再执行新问题。原会话的全部问答保留在历史中，新分支记录 `sourceConversationId`、`sourceMessageId`，页面提供查看原对话入口。分支标题继承原标题并添加“分支”，仍可手动修改。

旧问题及后续操作不会因修改而撤销。分支保留有界的旧写入回执提示，要求模型在再次写入前查询核对；受保护资源仍需要实际权限与授权。该提示不代替工具幂等性，也不保证不同意图的新请求绝不重复写入。

## 成对删除

删除前弹窗明确提示“问题和回答会一起删除，其余消息保留”。`message.delete` 删除指定用户消息及其相邻回答和时间线，通过 `message.deleted` 确认并返回最新快照。

后端从剩余可见消息、附件和工具回执重建模型工作上下文，清空旧的压缩摘要及压缩状态，避免被删除内容仍作为旧摘要进入后续模型请求。已有分支的业务执行提示、持久任务日志、用量、资源和应用业务记录保留；删除对话消息不会撤销账单、支付或其他已执行操作。

同一删除请求 ID 可返回已保存的确认结果，不会重复删除。保存失败会恢复内存中的消息和模型历史。会话版本冲突会拒绝操作，用户需重新连接获得最新会话后再处理。

## 回答复制与重试

回答下方提供复制、重试按钮，复制的是最终回答的 Markdown，不包括分析和工具时间线。回答头像移除，内容使用会话区域的完整宽度。

`message.retry` 包含回答 ID、请求 ID 和会话版本。它保留原会话、问题和回答 ID，在原位置流式显示新回答，不创建分支或重复问题。重试较早回答时，模型只使用该问题之前的问答、原问题及原工具事实回执；后面的问答继续保留显示，但不会自动重新生成，也不会进入此次重试的输入。重试沿用原问题的附件、所选应用、资源权限和本地日期。

原回答的文本、时间线、用量和完整工具回执写入独立的 `conversation_answer_versions` 表，新回答携带递增 `answerRevision`。归档旧版本和发布新快照在同一个数据库事务中完成；版本记录不塞进公开 socket 快照或常规模型上下文。重复请求只返回当前快照，原有费用记录不撤销，新模型调用按正常用量记录。

重试允许查询。对于写入或外部操作，执行器只复用原回答中参数匹配的真实回执，包括需要核对的失败结果；缺少可匹配回执的调用返回 `RETRY_SIDE_EFFECT_BLOCKED`，不执行账单写入、生图、外部请求等操作。需要重新执行应用操作应明确发送新消息。相同限制会随持久任务检查点恢复，不能通过断线或专业 Agent 委派绕过。

任务准入失败会恢复旧回答；连接中断先恢复会话，不自动发起第二次重试。旧回答版本保留在后台数据库；当前版本的删除仍需要成对确认，删除聊天消息不删除业务日志和旧回答审计版本。整个对话被删除时，版本表通过外键一并清理。

## 持久化与校验

分支来源、删除请求回执及分支业务提示保存在现有会话 JSON 状态和任务检查点中，无新增数据库表。公开 socket 快照仅暴露分支来源 ID，不暴露内部提示。

生成期间禁用修改和删除。后端同时检查本地运行锁、数据库任务租约、会话归属、资源权限及持久化版本；前端按钮禁用只是交互限制。

- `pnpm test`：包括消息命令、分支隔离、删除幂等与保存回滚测试。
- `pnpm test:ui-components`：包括暂停状态与消息操作可用性测试。
- `pnpm test:messages`：真实 MySQL 验证失败后发送、写入回执保留、分支持久化、成对删除、旧摘要清除和后续上下文，不调用收费模型。
- `pnpm test:answer-retry`：真实 MySQL 验证回答原位重试、版本持久化、工具复用及副作用限制，不调用收费模型。
