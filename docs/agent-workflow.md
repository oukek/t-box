# 可配置的任务分析流程

后端使用同一个普通会话模型完成需求判断、计划、工具处理、结果核对和最终回复；应用业务继续由独立应用的 Skills、Agents、工具和后端接口提供。这里没有通过正则或关键词选择应用。

分析阶段的宿主协议明确当前会话模型仅提交 `workflow_plan` 函数调用，不直接生成资源或调用模型内置工具。公开分析来自计划摘要；图片应用另外明确函数工具选择独立图片模型。普通会话运行选择与图片运行选择在读取数据库配置时再次校验用途，不能跨用途调用。服务商的固定“upstream request failed”错误按上游失败显示，HTTP 400 本身不等同于参数不兼容；普通模型失败的公开提示带会话阶段名称，避免与图片工具失败混淆。

## 运行阶段

新任务先进入 `dispatch`：同一次普通模型请求通过 `tool_choice=auto` 选择直接流式回复或提交 `workflow_plan`。简单问答、直接计算、现有事实足够的解释和必要追问不产生分析/核对时间线，不再单独请求一次最终回复；复杂推演或工具任务才保存计划。入口只开放计划函数，不能绕过计划执行任何业务工具。判断由模型按语义完成，没有新增关键词、正则或额外分类模型。能力目录在入口精简为应用、技能和工具名称/副作用；权限及执行验证保持原逻辑。

1. `analysis`：按模型配置的会话接口提交 `workflow_plan`，公开说明来自该调用的 `summary`，不要求模型同时输出正文。模型根据原用户请求、附件、上下文及已安装且符合当前 Agent 范围的能力目录，选择 `answer` / `clarify` / `execute`。计划记录步骤和必须成功的业务工具。阶段控制工具只能保存决定，没有业务副作用。
2. `execution`：工具由现有执行器调用，保持技能启用、资源授权、临时认证、幂等、安装状态、专业 Agent 隔离和前端等待机制。工具之间不额外调用一个分析模型，模型的每一轮可给出简短执行说明。未执行工具的文字是候选结果。单步产物任务可走下面的应用回执完成路径。
3. `review`：模型只能提交 `workflow_review`，对照当前任务真实回执确认完成、继续、提问或失败。后端独立核对计划中的必需工具是否真正成功，不能用文字候选结果替代成功回执。最多三轮核对，执行轮数仍受原有总预算限制。
4. `answer`：关闭所有工具，生成复杂任务的最终回复；入口已直接回答的任务不再进入此阶段。复杂纯推演可从计划直接到本阶段，跳过业务执行和核对。

新检查点保存 `workflowEntry=adaptive` 和 `dispatch` 的状态，断线恢复沿用已保存阶段；旧检查点不带该标志，继续使用原 `analysis` 协议，不能因升级重新路由或重复操作。入口若提交计划，其流式前文转为公开分析，不能误记为最终结果。多阶段及直接回复仍携带当前历史，并沿用原上下文压缩策略。

控制阶段只携带身份、权限边界、日期和本阶段数据；不拼入应用执行指令、技能正文或优先委派指令，也不调用应用的业务上下文查询。执行阶段仍按技能与应用提供完整业务指令。配置的指导不能改变宿主阶段协议或本次 tools 集合。

公开的是行动计划和事实核对，不是模型隐藏思维链；启用流程时不展示服务商 reasoning summary。响应中的 encrypted reasoning 仍留在内部上下文，符合 Responses 多轮协议。阶段控制调用具有完整 function call/output 对，但不会伪装成业务工具出现在用户工具列表。

## 图片等资源

图片应用已经提供 `images_generate`、`images_edit`，技能 `image_processing` 和专业 Agent `images`。主流程只读取注册目录，图片应用负责模型操作与验证。

工具 SDK 可声明 `completionSummary(result)`，由应用检查真实结果并提供可信的完成说明。规划目录只公开 `receiptCompletion` 能力标记，不公开回调。模型按用户语义选择计划的 `verification=receipt` 或 `model`：用户只要求单次操作、计划只有一步和一个必需工具、该工具支持回执完成、产物本身满足全部请求时才选择 receipt；要求解释、评价、多个操作或后续加工时选择 model。没有关键词识别或图片业务特判。

宿主再次检查当前任务真实回执：仅一个业务操作，其他只能是已成功的配置操作，所有回执必须成功，实际业务工具必须与计划一致，再调用应用自己的结果校验。图片应用只对包含一个有效图片资源的成功结果返回完成说明，不能用候选文字、空结果、失败或未知状态完成任务。这验证的是资源交付，不能声称已视觉核验内容质量。满足时直接发布最终 answer 和实际附件，省去候选、模型核对及模型总结请求；不满足则保留完整流程。旧任务没有 verification 时继续原模型核对流程。恢复依赖持久化回执，不重新生成图片。

默认分析 Prompt 明确区分生成、编辑、描述/识别：要求生图/改图时选择对应真实能力；看图交给支持视觉输入的普通会话模型。编辑对象必须是实际会话资源，缺少对象先询问。图片生成需要后台选定图片模型；未配置时工具明确失败。资源来自真实回执和附件，不允许编造下载链接或把文字说明作为生成结果。

这仍是模型的语义判断，不能保证所有模糊表达都零误判；不明确的意图应先提问，执行权限及写入校验不依赖模型判断。

## 配置与版本

- 后台「分析流程」：四个阶段的 Prompt 可以分别在弹窗中编辑或填入默认版本，保存时发布配置新版本。
- 管理接口：`GET /api/v1/admin/workflow`、`GET /api/v1/admin/workflow/defaults`、`PATCH /api/v1/admin/workflow`。沿用管理员认证和 CSRF 检查。PATCH 必须带原 `revision` 与完整 `prompts`，并发修改返回 409。
- TypeORM migration `AgentWorkflow1791244823000` 创建 `ai_workflow_configurations`（不可变版本，含管理员及时间）与 `ai_workflow_settings`（当前版本）。默认 Prompt 自动入库，已有版本不被启动覆盖。
- `WorkflowPhaseIsolation1791244826000` 只为完全未修改的旧内置 Prompt 发布新版本，消除正文与结构化决定的冲突；自定义 Prompt 及旧任务快照保持原文。
- 运行器通过配置端口加载快照，保存在任务 checkpoint；每个 Agent frame 保存阶段、计划、候选结果、核对结果及次数。继续任务沿用原配置，不因管理员修改而跳过授权或重跑成功写入。
- 生产组合根从数据库注入配置端口；底层执行器测试也可以不注入该端口，以单独验证基础工具循环。旧 checkpoint 没有阶段状态时，从其尚未结束的 frame 建立阶段；已保存的待执行工具及副作用记录保持原有恢复机制。

## 通讯、费用与错误

WebSocket 继续使用有序、带 revision 的 `timeline.update` / `timeline.delta`；公开阶段有 label，业务工具保留原位置。前端实时 Markdown 和打字机效果复用现有实现，最终回复完成后折叠之前的过程。历史归档保留顺序、标签、用量及错误字段。

每个阶段记录实际 usage：`analysis`（旧检查点分析）、`response`（自适应入口或任务处理）、`review`、`answer`、`compaction`。计费统一走 `MeteredChatProvider`，所有阶段按实际输入/输出 token 计费，标题仍免费。简单问题只有一次正文模型请求；首次标题仍是独立的免费请求，长历史触发压缩也可能产生摘要调用。推理模型默认输出预算 32768，其他模型 8192；预留费用随预算调整，实际账单仍只依赖服务商 usage。提高预算不代表固定消耗全部 token。

错误使用简短、可安全公开的原因，例如 401 鉴权失败、429 限流/额度不足、400 参数不兼容（含安全的 code/param）、连接失败、响应提前结束、输出预算不足或内容过滤。不会把上游请求/响应正文、密钥、URL、SQL 或用户输入原样返回。错误保存在消息 `error` 和任务 reason，并在 timeline 提示中显示。进度仍保存，结果不确定的副作用依旧进入原有 `needs_review` 机制，不自动重试。

核对或总结失败时，提示先列出实际已成功操作的应用完成说明，再标明未完成阶段和安全错误原因；附件、成功回执及费用记录继续保留。不能因后续会话错误将成功图片改成失败，也不能将复杂任务核对失败伪装成全部完成。后端日志增加经过格式校验的服务商 error code/type 和固定上游错误类别，帮助区分网关异常和参数错误，不打印原始错误正文。

后台运行错误日志另含经过格式校验的服务商请求 ID、HTTP 状态、内部错误代码和阶段，用于关联上游排查；不记录原始错误正文、请求头、密钥、SQL 或隐藏推理。基础接口测试成功不能证明复杂调用始终兼容，HTTP 400 的固定上游错误也不能单独证明代码参数错误。

任务恢复先无锁读取最多 256 个过期租约，再按主键更新，并重新校验状态和到期时间，避免范围 UPDATE 的间隙锁与新任务竞争。同一存储实例共享进行中的恢复扫描。会话归档及工具意图入库事务使用 READ COMMITTED，避免首次插入不同会话/工具回执时对不存在记录加间隙锁；已有会话仍通过行锁、revision、所有权、任务租约和唯一键保护，工具意图通过任务父行锁串行化。多个 API 实例初始化应用注册、后台提交应用时，直接获取注册行排他锁，避免 INSERT IGNORE 的共享锁升级死锁。遇到数据库死锁或锁等待超时，公开错误为 TASK_STORAGE_BUSY；不会自动重跑模型或业务副作用。

## 验证

- `pnpm --filter @t-box/api test`：阶段控制、语义决定驱动工具、普通会话跳过执行、真实回执检查、流式顺序、token 用途、错误过滤等。
- `pnpm test:workflow`：真实 MySQL 配置校验、管理员隔离、版本冲突、任务暂停/继续、沿用原 Prompt 版本、不重复写入、计费及历史持久化。使用临时账号和模拟模型，不调用收费模型。
- `pnpm --filter @t-box/api test:task-concurrency`：真实 MySQL 的 24 个首次会话并发创建、归档、租约与重复工具回执检查；使用临时账号和模拟模型。
- `pnpm --filter @t-box/api test:chat-routing all`：手动使用数据库中真实普通模型，分别走 Responses / Chat Completions 的完整入口，只问「1+1=多少」，断言一次正文调用及纯回复时间线。创建并清理临时账号，用量记录入库但测试余额不扣费；服务商模型请求本身可能收费，不进入自动测试，不修改模型选择。
- `pnpm --filter @t-box/api test:image-workflow`：真实 MySQL/资源存储及模拟模型，验证应用回执完成、附件交付、最终检查点故障后重启恢复且不重复生图。
- `pnpm --filter @t-box/api test:image-workflow-live`：手动使用当前真实会话模型检查单次生图的语义规划、技能和工具调用，图片工具输出本地测试图片，不请求图片模型。临时账号与资源结束后清理，用户测试余额不扣费，服务商会话请求可能收费。不修改模型选择。
- 模型连接测试与生产使用同一个 `createConversationProvider` 工厂，按模型的 `invocationMode` 选择 Responses 或 Chat Completions 适配器，测试强制工具选择、流式响应和实际错误提示。不会自动生成测试图片。

协议参考：[OpenAI Function calling](https://developers.openai.com/api/docs/guides/function-calling)。模型返回工具调用后，由应用执行并传回结果；后续 Responses 请求保留必要的 reasoning items。

## 模型调用方式

模型管理的「调用方式」存入 `ai_models.invocation_mode`，每轮任务解析一次并保持不变。现有会话模型迁移为 `responses`，图片模型迁移为 `images`。普通会话可选 `responses` / `chat_completions`；图片工具只调用 Images API，不能选作会话接口。需求分析、任务处理、结果核对、回复、摘要和免费标题均使用选中的会话适配器。

运行时继续持久化统一的 message / function_call / function_call_output 历史。Chat Completions 适配层转为 `messages` / `assistant.tool_calls` / `tool` 消息，按 index 拼接流式工具参数，响应完整后才执行工具。普通正文仍通过 WebSocket 发布；服务商的原始隐藏推理不展示。usage.prompt_tokens / completion_tokens 转为统一用量字段，缓存输入和推理 token 分项保留。截断或断流不执行半截调用，也不自动切换接口重试。

Chat Completions 不调用 `/responses/input_tokens` 或 `/responses/compact`，后台切换时自动关闭精确计数，原生压缩改为事实摘要。缓存键仅在配置明确启用时发送。切换调用方式会变更 configurationKey；新任务丢弃不兼容的加密推理，遇到原生压缩记忆时从原始会话重建，保留业务回执。仍含不完整工具对或不可移植记忆的检查点不能被伪造转换。

参考：[Chat Completions API](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。
