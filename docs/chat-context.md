# 会话历史与上下文整理

## 历史范围与持久化

每次调用携带当前会话的工作历史，包括用户消息、助手响应、附件资源引用、完整工具调用/回执；不会自动读取其他会话。专业 Agent 有独立工作历史，只接收当前用户请求、附件与明确委派任务，不继承主助手所有历史或其他应用数据。

原始 UI 消息、时间线、附件元数据、真实工具回执、幂等记录、写入日志与任务检查点独立保存。工作历史可以被压缩，但上述记录不会被摘要替换。重新打开会话恢复工作历史与压缩状态，继续任务恢复对应 Agent frame。更改预算/提示配置不会直接丢掉滚动摘要；变更服务商配置时去掉不可移植推理项，若工作历史包含原生加密压缩项，则用原始消息、附件和真实工具回执重建。

访问控制始终检查原始会话引用和当前身份/资源授权。摘要不能签发授权、解除账本密码、替代写入日志或自动重做副作用。密码/认证 token 仍由原有前端交互和授权服务处理，不进入工具模型参数。

## 配置及默认值

后台「模型配置 → 编辑模型」独立配置每个会话模型；配置保存在 `ai_models.context_policy` JSON，无需新建表。

| 字段 | 默认 | 作用 |
| --- | --- | --- |
| 输入预算 | 新模型 98304 | 发给模型的有效输入上限；旧模型原有预算保留 |
| 总上下文窗口 | 0（未知） | 由管理员按服务商文档填写，不根据模型名称猜测 |
| 输出预算 | 0（自动） | 推理模型 32768、普通模型 8192；可指定 1024–262144 |
| 压缩模式 | 事实摘要 | `summary` / `native` / `off` |
| 触发比例 | 0.75 | 每次调用前，输入达到有效预算的 75% 开始整理 |
| 保留最近用户轮数 | 4 | 优先保留最近四轮完整原文，过大则减少原文窗口 |
| 摘要目标 token | 2048 | 同时执行 UTF-8 大小校验，防止摘要本身过大 |
| 精确计数 | 关闭 | 可选 `/responses/input_tokens`，需服务商支持 |
| 稳定缓存键 | 关闭 | 可选 `prompt_cache_key`，需服务商支持 |

有效输入预算 = `min(输入预算, 总窗口 - 输出预算 - 1024)`；总窗口未知时只使用输入预算，管理员需确认其与输出之和不超过真实模型限制。总窗口填写后必须至少剩余 8192 token 输入空间。`max_output_tokens` 包含隐藏推理及可见正文，不能把全部预算视作可见回复长度。普通流式请求超时为 180 秒；任务仍有五分钟总执行期限，超时通过现有任务暂停/恢复机制处理。

未开启精确计数时，使用 UTF-8 字节、工具定义、指令和图片安全余量的**保守估算**，不是 tokenizer 实际值。图片 base64 编码长度不会作为文本 token；图片仍计安全余量。费用一律以服务商实际 usage 结算，缓存输入/推理 token 保留明细。提高输出上限也会提高计费预占上限。

旧配置的 `compaction=true` 继续解释为原生压缩；旧 `false` 原本只表示未开启原生能力，现统一升级为通用摘要。需要完全关闭时显式选择 `off`。已暂停任务仍遵循原有配置一致性检查；不能悄悄用变更后的模型/预算继续旧检查点。

## 每轮整理流程

1. 在需求分析、执行、核对、最终回复及专业 Agent 的每次模型调用前计数，包含最新工具结果和当前指令/工具定义。执行中的长任务无需等下次用户发消息。
2. 低于触发比例则沿用历史。上次压缩后的增长小于 `max(1024, 有效预算×15%)` 且仍在硬预算内时暂不重复整理，避免阶段提示小幅变化造成重复付费；超过硬预算始终重新检查。
3. 等待当前完整工具批次保存后才整理。并行调用及全部回执为原子组，不能拆开、遗留孤立回执或删除仍等待前端结果的调用。
4. 优先保留最近四轮完整原文。无法容纳时减少到一轮；单轮工具循环很长时，固定保留最新用户请求和最近完整原子组，把较早完成部分归入摘要。
5. 事实摘要模式按完整原子组拆分早期历史，最多八段。每段模型请求先做保守大小检查，逐段合并上一段记忆；只用普通会话接口，工具关闭，不产生应用操作。
6. 摘要保留目标、约束与否定、更正、授权范围、日期/金额/资源 ID、实际成功回执、失败和不确定状态、未完成事项与待回答问题。移除不可理解的加密推理；旧图片仅保留资源元数据和存在信息，不把图片字节放进摘要或臆测内容。
7. 只有全部分段完成、摘要大小有效、整理后输入在硬预算内且缩小至少 `max(256, 原输入×5%)` 时才替换工作历史。原始历史与压缩状态在失败时不提交替换。
8. 附件 projection 恢复为内部 `asset:` / `asset-text:` 引用再保存，禁止把模型请求中的私有图片 data URL 存为工作历史。

原生模式仅调用 `/responses/compact`，保留服务商返回的加密压缩项。不会在原生失败后偷偷再发一次付费摘要请求。加密原生记忆不能转为可读摘要；切换到摘要时需新建会话，或在配置变更时从原始历史重建。

## 时间线、账单与恢复

时间线按实际顺序插入「整理上下文」：开始 → 分段进度 → 整理前后 token 数（估算会明确标注）。与分析、工具、核对统一排序，最终回复出现后沿用既有自动收缩逻辑。摘要正文是内部事实记忆，时间线只显示整理状态；不会显示原生加密记忆或隐藏推理。

每个摘要分段有独立 operation ID、实际 token usage，消息和费用明细标为 `compaction`。标题生成仍不扣用户余额。失败保留已发生摘要调用的实际费用；后续继续不会重复成功的业务工具。工具回执归属保存在 frame 的 `receiptIds` 中，不依赖被压缩掉的模型调用历史；核对提示里的大回执只发送有明确截断标记的预览，真实必需工具成功检查使用完整执行记录。

## 失败边界

- 最新请求/附件、工具定义或系统指令本身超大，压缩旧历史无法解决，明确报错并建议减少附件或调整预算。
- 单个不可拆的历史消息/完整工具回执超出摘要输入容量，明确报错，不截断回执伪装成功。
- 摘要过大、服务商接口不支持、分段超过八段、压缩效果不足、模型或计数请求失败，保留原上下文并显示简短错误；不会盲目重试付费调用。
- 摘要是有损压缩，无法承诺任何历史细节永远留在模型上下文。涉及精确核对应使用应用查询工具/真实执行记录，不能只相信摘要。
- 压缩只控制模型输入，不是无限存储：任务检查点仍有 2MB 安全上限，每个会话最多 1000 个请求，不清除幂等标识。原始消息和大资源持续增长仍可能达到存储保护限制，届时提示新会话；资源内容按既有容量策略读取。

## 验证

`pnpm test` 包含纯策略、完整调用对、当前轮压缩、分段失败原文保护、资源引用、精确计数、窗口/输出预算与重建回执测试。

`pnpm test:context` 使用临时 MySQL 用户、任务、会话和账单及本地伪模型：验证长工具循环中整理时间线、早期回执核对、分段独立计费、429 暂停后恢复、持久化状态和重开当前会话。测试不调用付费模型，也不写入真实用户业务数据。
