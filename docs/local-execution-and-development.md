# 本地计算与 workspace 开发

## 应用执行边界

| 应用 | 页面本地执行 | 后端保留 |
| --- | --- | --- |
| 计算器 | 表达式和 16 类数学计算，使用 `calculator-contracts` 中同一套算法 | AI 工具及受控 API 调用相同算法 |
| 单位换算 | 目录、换算、精度和校验，使用 `converter-core` | AI 的目录、单项与批量工具 |
| 日历 | 月历、星期、日期、农历转换、节气与节日算法；使用共享的校验和重复规则 | 已保存日程、单次状态、账号权限、提醒计划、官方调休数据和 AI 工具 |
| 时间 | 世界时钟显示、时间戳、时区、时间差、日期加减、倒计时剩余量和秒表；使用 `time-contracts` | AI 的当前时间与时间计算；倒计时创建、控制、删除、权限、幂等和服务端校准 |

纯函数在前后端复用；前端不为一次数学或日期换算请求接口。新应用可以像单位换算一样拆出 `core`。历史应用已在 contracts 中维护共用函数，不在前后端复制另一套算法。

日历的日程列表查询需要账号事件和单次状态，不能因为其中包含重复展开算法就绕过后端读取权限。前端仍不必等日程或调休数据加载完才能绘制月历、计算农历与节气。节日日期也不等同于国务院公布的放假安排。

倒计时的剩余量与状态转换函数共用，但客户端计算不代表写入成功；创建/暂停/恢复等操作继续由后端事务和版本检查确认。秒表算法已从 Web 私有代码移入共享包，客户端只保留兼容导出。服务端 AI 不依赖浏览器保持打开。

计算器历史和时间偏好改为页面显示后异步恢复。迟到的读取不能覆盖刚清空的记录、刚开始的秒表、修改后的世界时钟或新账号状态。SDK 存储由宿主按用户和应用隔离，当前为设备本地存储，不表示跨设备同步。

## 为什么以前会发生 Failed to resolve import

包的公开入口原先指向 `dist`，Vite 同时依赖 pnpm 的 workspace 链接。单独启动前端、刚添加包、构建产物被清理或编译与热更新不同步时，可能出现找不到入口或读取旧产物的问题。只重建报错的一个包不能解决启动和解析方式的根因。

所有前端 Vite 配置现在使用 `scripts/vite-workspace.mjs`：

1. 从 `pnpm-workspace.yaml` 发现包，读取各包 `exports`，支持根入口与子路径通配符。
2. 将约定的 `dist/*.js` 浏览器入口解析到对应的 `src/*.ts`，直接编译和热更新源码；不依赖 dist，也不为每个新应用手写 alias。
3. 使用同一个 Vue 实例，并避免将 workspace 包预打包成过期依赖缓存。
4. 检查调用方声明的依赖，不开放未导出的私有路径；缺少源码入口时明确失败。
5. 包声明、workspace 列表或锁文件变化后，开发服务器自动重新扫描并刷新依赖优化状态。

这套源码解析用于浏览器开发和 Vite 构建。生产 Node API 仍使用已编译 dist，部署包继续通过 workspace 依赖顺序构建，不在服务器执行 TypeScript 源码。

## 启动与验证

首次拉取仍需安装 pnpm 对应版本。根目录执行：

```bash
pnpm dev
```

启动器依次执行 `pnpm install --frozen-lockfile --prefer-offline --prod=false`、构建 Node 依赖与应用声明，再启动 API。`/api/v1/health` 确认 MySQL 可用后，才启动宿主、后台、全部独立应用和产物服务。准备成功只显示阶段摘要；失败保留完整输出。健康检查最多等待 90 秒，失败会保留 `[api]` 错误并停止服务。Redis 是可选缓存，不阻塞网页启动。锁文件与 package.json 不一致时，先运行 `pnpm install` 更新锁文件；不会在启动时擅自改锁。

API 开发命令通过 `scripts/dev-api.mjs` 生成仅用于开发的 tsconfig，按 workspace 的公开 `exports` 把 Node 包的 dist 入口映射到对应 src；根入口、子路径与传递依赖使用相同规则。`tsx watch` 直接监听实际使用的源码，因此不再为每个包同时运行一个 TypeScript 编译器，也不会在启动时因为批量改写 dist 反复重启 API。生产构建仍按依赖顺序生成并使用 dist。`pnpm dev:packages` 仅供需要观察编译产物的独立开发流程使用，日常 `pnpm dev` 不需要同时运行它。

保持终端运行，看到「API 就绪」和 Vite 地址后访问主站；Ctrl+C 一起停止全部服务。

| 服务 | 默认地址 / 端口 |
| --- | --- |
| 主站 | <http://127.0.0.1:5173> |
| 管理后台 | <http://127.0.0.1:5175> |
| API 健康检查 | <http://127.0.0.1:6868/api/v1/health> |
| 计算器、记账、日历、时间、换算、宝宝日记 | 5176、5177、5178、5179、5180、5181 |
| 已构建应用资源服务 | 6176 |

子应用开发端口需要宿主 SDK 握手，不是供用户直接打开的独立登录入口。统一从主站的 OS 桌面或应用市场打开。手机调试使用电脑局域网 IP 的 5173 端口。平时固定使用 localhost 或 127.0.0.1 中的一个；两个地址的登录状态和设备缓存互相独立。

### 本地测试应用发布和更新

`pnpm dev` 提供 Vite 源码热更新，默认注册的 `sha256-000…` 是开发预览占位值，不是正式安装包，不能直接上架。后台将其标为「开发预览」。要测试真正的产物校验、发布与安装更新，在项目根目录执行：

```bash
# 只构建并提交宝宝日记；也可换成 calculator、calendar、time、converter、ledger
pnpm apps:submit:local baby-diary

# 构建并提交全部独立应用
pnpm apps:submit:local all
```

命令复用 CI 的构建格式，生成真实文件摘要，将产物保存到本地 6176 服务目录，再写入本机开发数据库，状态为「待发布」。刷新后台「应用管理」，填写更新说明后手动发布；已有安装仍需在应用市场确认更新。此命令不会自动上架、修改旧版本产物或变更安装权限，也不改变 Vite 热更新配置。内置的设置和应用市场随宿主发布，不在独立构建列表中。

同一版本与相同产物重复执行会复用原记录，不覆盖后台填写的信息。同一版本已经绑定其他产物时需要提高应用版本号，不能原地替换；已有开发预览占位记录不占用正式构建的版本号。后台也支持从预览记录「选择产物创建发布草稿」。

此入口只支持本机开发数据库和本地产物服务，正式环境继续使用 GitHub Actions → OSS → 服务端入库 → 后台手动发布流程。已锁定的真实版本如果使用了旧产物服务地址，需要提交新版本；不能通过跳过地址或摘要校验来发布。

## 数据库与常见启动问题

- `api/.env`：首次拉取从 `.env.example` 复制并填写；已有配置不要覆盖。MySQL 必须启动。使用 Redis 时同时启动 Redis；暂不使用可将 `REDIS_ADDR` 留空。
- 新的空数据库：先 `pnpm install`，再 `pnpm db:init`、`pnpm admin:init`；普通用户可从网页注册，或可选运行 `pnpm user:init`。
- 已有数据库：日常直接 `pnpm dev`。`db:init` 不是升级工具，也不会自动接管旧迁移库。额度体系现已使用新基线 `2026-10-23.2`，旧库不能直接用于当前代码，请配置新库并初始化，原库保持原样。按 [数据库初始化与升级](database-initialization.md) 选择对应流程。
- `ECONNREFUSED ...:3306` / MySQL 连接失败：检查数据库服务及 `.env` 的地址。`Table ... doesn't exist`：核对当前连接的数据库与初始化/升级状态，不要删库重来。
- `EADDRINUSE` / `Port ... is already in use`：另一个开发进程占用了端口，先在对应终端 Ctrl+C 停止旧进程；不要同时运行 `pnpm dev` 和单独启动命令。
- `Found 0 errors` 是 TypeScript 成功提示，不是业务报错；新的完整启动不再启动大量包编译监听器。开发模式也不再逐条输出成功 HTTP 请求，错误日志仍保留。
- 未配置 AI 模型或密钥时，会话提示未启用是正常业务状态，不妨碍登录和本地工具。通过后台配置服务商及模型后生效。
- 登录页与通用表单样式由宿主和 `@t-box/ui-kit/base.css` 提供，不依赖记账应用是否打开、安装或发布。修改启动脚本后先停止旧进程，重新 `pnpm dev`，再刷新页面。

排错时可用 `pnpm dev 2>&1 | tee dev.log` 保存日志，优先看首个 `[api]` 错误或 Vite 的红色错误；不要把 `.env`、密钥或账号密码粘贴出来。

已经安装依赖后也可以单独运行 `pnpm dev:app`、`pnpm dev:admin` 或独立应用的 dev 命令，浏览器仍直接解析源码。新增外部 npm 依赖必须正常安装；源码入口拼写错误、未声明依赖、权限失败和真正的业务错误不会被“兼容”逻辑隐藏。

修改 Vite 配置、包 exports 或新增 workspace 包后，完整启动命令需要重启一次，以重新生成 Node 源码入口；无需为新应用手写解析别名。新应用生成器也已包含统一插件。

回归测试覆盖：没有 dist 和 node_modules 链接的临时 workspace、过期 dist、跨包与子路径导入、未声明依赖、原先的 shared/converter 报错路径、开发准备失败，以及偏好延迟和账号切换。
