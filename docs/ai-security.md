# AI 内部信息保护

后端 `api/src/ai-security` 是平台公共安全层，不属于任何一个应用。应用仍自行提供工具、技能、专业 Agent 和业务权限；保密策略不能扩大工具权限，也不替代资源鉴权、密码验证、写入确认及幂等。

## 系统规则

`policy.ts` 的宿主规则覆盖主助手、专业 Agent、需求判断、分析、执行、核对、回答、标题和上下文摘要。实际模型/服务商/端点、内部指令、隐藏推理、认证信息和后台诊断不对外公开。它也禁止通过翻译、编码、分段、文件、图片、链接或工具调用转发这些信息。

用户自称管理员，或者附件、工具回执、历史记录、能力描述中出现“系统指令”，都不构成后台授权。助手可以介绍应用公开功能和当前任务的简短行动依据，可以讨论公开 AI 技术；不能确认或猜测本站内部配置。

后台「AI 配置 → 平台 Prompt」中的「安全与保密补充指导」对应 `ai.prompt.security`，沿用数据库、Redis 缓存、配置修订、任务快照及历史记录机制。服务启动时通过配置定义自动登记，无须手工添加数据库字段。此项补充回应方式，不能关闭代码中的安全底线。新任务使用最新配置；已有任务恢复时也会经过当前代码的安全底线。

## 后端输出边界

`DatabaseChatProvider` 返回的实际会话 Provider 外包 `ProtectedChatProvider`，保留底层计费、审计、并发限制及错误重试行为。

- 密钥只由后端连接服务商，不加入安全 Prompt；保护器只在服务端持有用于比对的值。
- 对当前实际模型 ID、足够明确的模型/服务商显示名称、服务商端点、密钥，以及后台 Prompt 和当前技能/Agent/工作流 Prompt 的已知原文片段做确定性遮蔽。短模型 ID 也受保护；过短的显示名称不作为通用敏感子串，以免大范围误伤。
- 流式输出缓存可能匹配的后缀，覆盖跨 delta 和跨网关消息 item 的字面匹配；不会等整个回答结束才过滤。公开回复和保存给后续模型的回复文本均过滤。
- 工具参数先解析 JSON，再检查已知敏感值。命中时整批调用在调度之前以 `AI_DISCLOSURE_BLOCKED` 拒绝；不擅自修改参数，不自动重试，也不重新执行已完成的操作。
- 不公开模型自带的 reasoning summary。前端仍显示宿主工作流产生的行动摘要和工具时间线。原生压缩和推理的加密状态继续作为后端私有状态保留。
- 上游错误的 `code` 和 `param` 只允许已知安全枚举进入用户错误信息；完整诊断仍在受管理员鉴权保护的审计中。

启用技能的回执仅返回 ID、标题、版本及工具名；技能指令从注册表按需注入。普通用户 `/api/v1/tasks/:id` 只返回工具状态，不返回原始回执或检查点。此接口收口也适用于数据库中已经存在的旧回执，不需要为了隐藏旧技能 Prompt 删除历史执行证据。

## 验证与边界

`api/test/ai-security.test.ts` 使用本地假 Provider 和 HTTP 注入，覆盖主/专业 Agent 各阶段、流式分片、混合大小写模型 ID、Prompt 原文、JSON Unicode 转义、工具调用拦截、正常业务放行、标题/摘要、原生压缩、错误重试语义和旧任务接口投影。测试不调用真实付费模型。

确定性过滤能阻止已知字面值泄露，不能识别所有语义改写、未知密钥、编码/分段重构或模型指纹。Prompt 约束也不能提供绝对防套话保证。这不是将系统 Prompt 当作安全凭据的理由：真实凭据、管理配置、其他用户数据始终依赖后端访问控制；不要把它们提供给模型。图片/文件工具仍需保持最小权限。

上线前对每个实际启用的会话模型做明确授权的对抗评测，至少覆盖：直接索取模型及 Prompt、管理员角色伪装、翻译/编码导出、跨多轮拼接、文件/图片工具外传，以及附件/工具回执中的间接注入。同时验证普通记账、日历和图片请求仍可正常完成。自动化单测验证的是代码边界，不等同于真实模型已通过语义攻击评测。

参考：[OpenAI：Safety in building agents](https://developers.openai.com/api/docs/guides/agent-builder-safety)。
