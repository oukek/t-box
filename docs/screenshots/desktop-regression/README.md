# 第 09 项 · 桌面版本组合与异常恢复

2026-11-25，macOS 27.0.1，Apple Silicon。使用两个独立构建并签名的本地验收客户端、独立应用数据目录和回环更新渠道。客户端通过正常更新入口下载和安装；测试渠道用于提供指定目标、注入坏包及中断连接。另用真实 MySQL 和内存对象存储测试后端发布与差量查询。以下版本均为验收版本。

## 版本组合

下载量取自成功尝试的制品响应体，不含检查请求、清单、HTTP 开销及此前有意失败的尝试。每条更新路径从点击一次确认或重试开始；进程号、主窗口数量、实际运行版本及发布记录在结束时核对。

## 异常与恢复

| 注入的故障 | 实测结果 |
| --- | --- |
| [磁盘空间不足](01-storage.png) | 将验收应用的更新目录置于独立的 24 MiB 卷，剩余 815,104 B，写入 2,728,440 B 的界面包失败。旧进程和版本保留，未产生待激活记录。释放该卷的测试占位文件后，从原弹窗点「重试」成功。当前文案为「无法保存更新文件」。 |
| [核心签名错误](03-core-signature.png) | 替换核心签名，下载后拒绝安装。保留已确认的界面和运行核心。恢复正确签名，从同一弹窗重试升级成功。 |
| [已签名的新版界面无法启动](06-fallback.png) | 发布签名有效、没有启动脚本的界面 1.1.36。等待握手超时后，原进程恢复已确认的 1.1.35，核心保持 1.0.14，待激活记录清空。无历史包时回到内置界面的实测见[第 06 项截图](../desktop-signed-update/11-bundled-fallback.png)。 |
| [下载中强制结束进程](07-crash.png) | 原生记录已经标记下载中时强制结束验收进程。重新打开自动提示上次下载中断，保留 1.1.16 / 1.0.0，启动后清除中断标记。 |
| [网络传输中断](08-network.png) | 渠道发送界面包前 131,072 B 后断开。下载解锁，提供重试和返回旧版，运行进程保持。 |
| [界面签名错误](09-ui-signature.png) | 对内容和摘要正确的界面包返回另一份签名，客户端拒绝启用，原进程仍运行，没有待激活版本。 |
| [安装交接后仍启动旧核心](11-install-recovery.png) | 在隔离目录注入等待核心 1.0.15 的安装记录，实际启动 1.0.14。客户端清除未完成的计划，保留上一条成功发布记录，恢复可用界面。此项模拟安装交接中断。 |
| [更新服务不可达](12-offline.png) | 更新渠道收到检查后断开连接。客户端从本机冷启动 1.1.35 / 1.0.14；手动检查提示服务暂不可用，保留上次成功检查时间。 |

## 发布端与兼容性

MySQL 集成测试覆盖同一候选并发登记、同编号绑定不同内容、缺包、错误架构、签名错误和协议不兼容。两个候选同时基于同一线上版本发布时，只有一个成功。跨版本设备得到获胜发布的差量计划，任一组件比已发布目标更新时不会下发降级计划。旧发布的核心清单返回 404，macOS x86_64 查询返回 204。

```sh
MYSQL_DATABASE=t_box_test_phase09 pnpm --filter @t-box/api exec tsx test/desktop-releases.integration.ts
node --test scripts/system-version.test.mjs scripts/desktop-check.test.mjs
cargo test --manifest-path desktop/src-tauri/Cargo.toml
```

当前发布渠道支持 macOS arm64、桥接协议 1。Windows 和 Intel Mac 未做安装验收。客户端自动恢复已确认界面与管理员主动撤回已发布版本是两项能力。后台目前没有主动撤回或指定旧摘要回滚的入口，也没有为未来跨协议客户端配置必经中间版本的功能。不可启动的原生二进制需要外部修复安装包，本轮未执行生产签名安装或线上恢复演练。
