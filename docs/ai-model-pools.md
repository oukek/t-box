# 模型池、并发与任务审计

## 配置入口

1. 后台「服务商管理」保存连接和密钥，设置**服务商总并发上限**。0 跟随「平台配置 → 成本与并发 → ai.provider.concurrency」，默认 8。多个模型共用同一服务商时共享此额度；同一真实上游账号不要重复建立多个服务商来绕开总量限制。
2. 「模型管理」为每个模型设置用途、接口、能力、价格和**模型并发上限**，默认 4，允许 1–128。
3. 点击「配置」打开模型池，分别多选普通会话模型、图片生成/编辑模型，每个用途最多 32 个。不选择则关闭该用途，不会启用本地规则或其他模型兜底。首次升级会把原先的单个配置迁入模型池。
4. 池配置、模型与服务商参数保存在 MySQL。候选配置沿用 revision + Redis 缓存，缓存中只含密文密钥，运行时解密。修改后新任务生效。

普通会话池用于回复、分析、工具循环、标题和上下文整理；图片池独立调用 Images API。仅配置为支持图片输入的会话模型参与看图任务。模型/服务商禁用、删除前必须先移出模型池。

## 调度语义

- **按新任务分配模型**。先比较模型和服务商的当前占用率，两者取较高值；较低者优先，负载相同则选择最久未分配的模型。不同并发能力的模型按占用率比较，不要求请求数绝对均分。
- 排序与轮换序号由 MySQL 短事务串行维护；API 与独立 worker 共享路由状态及在途租约，不依赖单进程的内存计数。
- 一旦选定，同一任务的各阶段、工具循环及自动重试固定模型，已执行的工具不因模型重试重复执行。手动/后台续办按检查点找回原模型，而不是重新轮换。原模型移出池、停用或接口/上下文配置改变会明确阻止旧任务续办。
- 新一轮切换模型时重建可移植的会话历史与工具回执，不向其他模型发送前一个模型的私有推理/压缩状态。跨模型通常不能复用原服务商的原生缓存；并发均衡与缓存命中率存在取舍。
- 模型和服务商两层硬并发租约约束**实际请求**。选中模型后如果槽位满，会等待；排队不会提前预留钱包。`ai.provider.queueTimeoutMs` 默认 30 秒，超时返回繁忙提示，不能绕过限制。两个模型共用服务商时，模型上限的和也不能突破服务商上限。租约的数据库死锁仅重试 SQL，不重新调用模型；释放失败保留租约等待过期，不覆盖已经成功的结果。
- 服务商失败会将该模型暂时冷却，默认 5 秒起、指数增加至 60 秒；`ai.routing.cooldownBaseMs` / `ai.routing.cooldownMaxMs` 在平台配置修改。新任务避开冷却模型，全池冷却则提示稍后重试。正在执行的任务遵循既有最多 5 次单请求重试策略，不在中途换模型。排队繁忙、钱包/预算错误、用户取消不会被当成服务商故障。
- 图片请求属于有副作用的外部操作，结果不确定时不自动重试，避免重复生成与扣费。单次运行内固定所选图片模型；续办后的新图片操作是无状态请求，可以重新调度，既有已完成或不确定的操作不会重放。

模型目录里的管理员连接测试也参与这两层并发限制；它是独立诊断请求，不属于用户任务，不向用户钱包扣费，服务商仍可能收取费用。

这里限制的是同时在途请求数，不等同于上游 RPM/TPM 限额，也不能保证服务商永不返回 429。

## 后台任务与逐次调用

「任务与运行记录」保留概况与异常事件，新增两个分页列表，页面可见时每 5 秒刷新：

- **任务列表**：按任务查看用户、任务/会话/请求 ID、Agent、状态、恢复次数、模型请求数/重试次数、历史模型/服务商快照、累计 token/费用/实扣、待核对用量和失败原因。可按用户账号/昵称或 ID 搜索、按状态/模型/服务商筛选。
- **逐次模型调用**：每个实际请求独立记录，即使没有关联任务也能查询；包括排队、运行、成功、失败、取消、中断状态。重试与原请求具有相同逻辑请求 ID，但独立调用/计费 ID、重试序号。
- 调用详情包含模型标识、服务商、接口、阶段、输入输出、token/缓存/推理用量、图片数、排队/总耗时、费用快照、服务商请求/响应 ID，以及**用户可见错误**与**底层错误**。token 计数端点没有计费流水时明确显示未计费记录，不虚构用量。未返回 usage 则保留未知与待核对状态。
- 任务完成/暂停时另存最终回答快照。用户之后重试同一条消息不会覆盖旧任务结果；逐次请求原输出也不覆盖。
- 元数据表 `ai_model_calls` 在发出请求前落库，25 秒续约，90 秒失联后管理查询将它标记为中断；此状态与计费账本独立，不代表请求未被上游接收。已有任务与流水可继续查询；升级前的详细请求输入输出及已删除模型名称无法补录。

调用审计只通过管理员认证接口读取，HTTP `Cache-Control: no-store`。不会把模型/服务商信息泄露给前端用户。二进制、私有推理密文、结构化认证字段及已知服务商密钥被省略，超长内容按 `ai.audit.maxPayloadChars`（默认 262144 字符）截断；剩余内容可能包含用户数据，数据库备份/后台访问需要按会话数据保护。普通异常概况仍仅含故障元数据。不要把这页导出为公开日志。

费用按请求选定模型的单价快照结算，标题仍不扣用户余额。用户端费用说明只展示可用模型池的价格范围，不展示模型名称。模型配置价格为平台记账价格，不必然等于上游账单成本。

## 升级与验证

部署前按既有备份流程备份，在新版本 API/worker 接收任务前执行 `pnpm db:init`。新增模型池、路由健康和调用审计表，沿用原数据与单模型指针。不要使用 TypeORM synchronize 替代迁移。

```sh
MYSQL_DATABASE=t_box_test_models pnpm db:init
MYSQL_DATABASE=t_box_test_models pnpm --filter @t-box/api exec tsx test/model-pools.integration.ts
pnpm --filter @t-box/api exec tsx --test test/model-audit.test.ts
```

集成用例仅使用隔离测试数据库和本地模拟 OpenAI 接口，覆盖多进程轮换/负载/并发、模型固定、图片独立池、服务商重试和冷却、费用快照、脱敏输入输出、任务最终结果、管理员鉴权、异常恢复与分页筛选，不会调用真实付费服务。
