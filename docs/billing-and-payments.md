# AI 额度、资源包与支付

实施规则、默认商品和验收清单见 [资源包实施规格](ai-resource-pack-implementation.md)。项目未上线，直接使用新基线，不兼容人民币余额充值、旧充值规则或旧库。

## 后台操作

1. 在「服务商」「模型」配置连接和模型用途。模型输入、输出价格为人民币 / 百万 token，图片价格为人民币 / 张，采购倍率 1 表示原价、0.8 表示八折。这些只用于内部成本，不决定用户额度价格。
2. 在「资源包与费率」配置公开文本费率、缓存输入费率、图片生成/编辑各分辨率价格及单任务上限。初始文本价格是草案，默认未启用；确认后勾选启用并发布。新版本适用于新任务。
3. 同页编辑资源包草稿，然后发布商品版本。价格、基础额度、赠送、有效天数、说明、排序和上架开关均入库并按配置版本缓存。资源包编码创建后不能修改。发布校验含赠送额度后的单位价格梯度，避免多个小包比大包便宜。下架不影响已购权益。
4. 「用户与额度 → 扣费设置」可将任意普通用户设置为「免费用户」。调用仍记录 token、图片、应扣额度、实际成本和错误，不预占、不实际扣额度，仍遵守任务、并发和成本预算。设置从下一次实际调用生效；进行中的调用保留原模式。操作必须填写原因并审计。
5. 可赠送额度并设置有效天数；赠送形成独立批次。异常用量可以核对并确认免扣，不能凭估算向用户追加扣减。

管理员是独立账号，免费用户不是管理员，也不会获得额外业务权限。

## 计量与实时结算

人民币支付使用整数分；供应商成本使用整数微元；用户额度用整数原子单位，1 额度 = 10000 原子单位。三者独立计算，禁止浮点资金运算。

调用前按保守输入和实际允许的输出上限预占额度，数据库账户锁串行同账户授权，批次按到期时间、发放时间、ID 消耗。实际 usage 一到达即结算，退回多余预占；不等待整轮会话或用户确认。服务商超出授权上限时用户最多扣已预占部分，完整应扣及上游用量仍记录，并输出 `QUOTA_AUTHORIZATION_EXCEEDED` 告警。

文本按输入、缓存输入、输出 token 分别计算；缓存 token 不重复计入普通输入，推理 token 包含在服务商报告的输出中。图片按请求分辨率独立收费，每个计费单元生成一张；2K/4K 需要图片服务商支持相应原始输出，返回图像短边低于请求档位时不扣额度，不用放大图片伪造分辨率。

标题、记忆整理、自动上下文压缩由平台承担。普通分析、专业 Agent 调用按实际请求计价。工具本身没有额外 AI 费用，图片工具除外。免费用户保留完整的理论额度消耗与成本。

每次模型尝试都有独立 ID，并关联逻辑请求、重试序号、用户、任务和消息。供应商请求重试复用执行检查点，不重跑已完成的工具；最多重试五次，错误分类和退避沿用通用运行策略。明确失败后释放预占；如果失败发生在 usage 已结算之后，则冲正原批次扣减，保留上游成本。缺失 usage 不伪造用量，标记待核对，不保留用户的无限预占。执行中的请求每 25 秒续期；进程遗留预占失联超过十分钟由恢复扫描释放，保留成本审计。

过期额度不会再参与新授权；过期前取得的有限预占仍可结算，余量释放/失败冲正时进入已过期部分。始终满足：发放 = 可用 + 预占 + 已使用 + 已过期 + 已收回。

## 用户页面与通知

AI 中心提供「我的额度」「AI 费用说明」。额度页展示资源包剩余、到期时间、使用记录、分摊、额度流水和购买订单。购买页仅显示已上架资源包；不再支持自定义人民币充值。商品名称、额度、赠送、人民币售价和有效期从后端读取。

用户接口不返回服务商、底层模型、采购成本或凭据。`/wallet/ws` 经用户会话认证推送变更提示，客户端重新读取数据库快照，不自行计算余额。本进程提交立即推送；独立 worker/其他进程变更通过五秒数据库核对发现。重连、前台唤醒和失联降级刷新均重新获取快照。Redis 只缓存配置，绝不批准扣减。

iOS 原生端仍可查看额度、资源包和记录，购买按钮保持禁用，限制提示只出现在购买页。网页和 Android 沿用微信支付。

## 微信支付与退款

支付页面保留 PC Native 扫码、微信外移动浏览器 H5、微信内 JSAPI 和 Android 原生 APP 模式。API v3 独立适配器负责请求签名、响应/回调验签和 AES-256-GCM 解密。公众号 OAuth state 绑定用户、订单、商户配置，十分钟有效且单次使用；openid 加密保存，不交给 AI。

下单只提交 `packageId`、`version` 和 Idempotency-Key。服务端核对当前上架版本并冻结商品快照，金额由服务端计算；同一幂等键不得更换商品或版本。订单三十分钟有效，同一账户最多十个有效待支付订单，首次下单锁定支付模式。

前端支付成功回调不能发放权益。只有验签通知或可信查询确认商户、订单、实付金额、币种和支付时间一致后，才在同一个数据库事务中置 paid 并创建一个资源包批次。基础和赠送额度共同绑定原订单，支付时间起计算有效期，重复通知不会重复发放。本地关闭后到达的有效成功通知仍履约。

退款只能由后台发起，先冻结原订单未使用权益，包括对应赠送比例，不占用其他包。人民币退款 = 原实付分 × 未使用权益 / 原发放权益，向下取整到分；正在使用的预占须先完成。微信请求分别提交实际退款分及原订单总分，不能把部分退款额当作原总额。渠道成功后收回权益，关闭则退回原批次（已过期的仍为过期）。未知结果保留冻结，通过原商户退款号核对，不能盲目创建新退款单。

## 配置与部署

在「支付订单 → 微信支付配置」填写服务号 AppID、商户号、API 证书序列号、商户私钥 PEM、32 字节 API v3 密钥、支付公钥 ID/PEM 或平台证书、公众号授权信息、网站与回调 URL。密钥加密入库，主密钥 `api/.secrets/provider.key` 必须与数据库一起备份，部署不能重新生成。

微信支付通知为 `/api/v1/payments/webhooks/wechat`，退款通知为 `/api/v1/payments/webhooks/wechat/refunds`。服务器需可公网 HTTPS 访问，配置公众号授权域名、JSAPI 支付目录、H5 域名、APP 应用身份及相应产品权限。代理应正确传递客户端 IP；只信任已配置的代理地址。宝塔/Nginx 应放行 REST 与 WebSocket 转发，支付通知保持原始请求体，不得由网关改写后再验签。

使用数据库基线 `2026-10-22.2`。PM2/Docker 仍通过 `node dist/init-db.js --check` 预检，空库执行 `node dist/init-db.js` 初始化。旧开发库不会自动转换、覆盖或删除，请配置新数据库后初始化。发布工作流保持手动触发，不需要增加新密钥或构建依赖。

## 主要接口

用户（均须登录）：`GET /wallet`、`GET /wallet/lots`、`GET /wallet/packages`、`GET /wallet/pricing`、`GET /wallet/usage`、`GET /wallet/entries`、`GET /wallet/refunds`；`POST /payments/orders` 接收 `{packageId,version}`。订单、支付意图、OAuth、查询与关闭路径保持现有支付协议。

后台：`GET/POST /admin/billing/packages`；`PATCH /admin/billing/packages/:id` 接收 `{draft,revision}`；`POST /admin/billing/packages/:id/publish` 接收 `{revision}`；`GET/PUT /admin/billing/tariff`（发布传 `{configuration,version}`）；用户扣费模式、赠送、用量、订单、退款管理仍由对应模块负责。

测试：`pnpm test:billing` 创建并清理随机测试库，覆盖并发、跨包、到期、免费模式、预算、异常超量、失败冲正、商品快照、重复支付通知和按比例退款。`pnpm test` 包含额度数学、价格梯度和微信签名测试，不调用真实模型/支付。
