# 方舟微信 UnionID 配置：从绑定服务号到验收

**先做第 1–3 步关联微信账号，再做第 4–5 步部署和验证。** 如果你现在只要让现有服务号开始积累 UnionID，做完第 1、2、4、5 步就可以；iOS 移动应用的微信审核可以同时进行。

| 操作前记下来 | 方舟要用的值 |
| --- | --- |
| 服务号 AppID | 去第 1 步复制，形如 `wx…`。现有网页和扫码登录使用它。 |
| 移动应用 AppID | 去第 3 步复制，另一个 `wx…`。留给原生 App 登录。 |
| iOS Bundle ID | `cn.tboxos.ark` |
| Apple Team ID | `8BQ285B3J2` |
| 微信 Universal Link | `https://tboxos.cn/wechat/`，包括末尾斜杠 |
| 服务号网页授权域名 | `tboxos.cn` |

UnionID 由微信按用户返回，你在后台要做的是把服务号和移动应用放到**同一个微信开放平台账号**。你的微信、同事的微信各有自己的 UnionID。没有一个适用于所有人的 UnionID 可以填进 GitHub 或方舟设置。

## 1. 找到方舟正在用的服务号

1. 打开[方舟管理后台 → 微信登录](https://admin.tboxos.cn/#/wechat-login)，记下现在的「认证服务号 AppID」。现网登录正常就保留原配置。
2. 打开[微信公众平台](https://mp.weixin.qq.com/)，用管理员微信扫码，选择运营方舟的**服务号**。在「设置与开发 → 基本配置」或账号的开发信息页面找到「开发者 ID（AppID）」。如果页面提示去开发者控制台管理，跟随页面入口，在同一个服务号下查看。
3. 对照两处 AppID，须逐字一致。记下服务号名称和原始 ID（如绑定页要求填写）。在服务号的账号信息、接口权限里核对认证状态及网页授权权限。查看 AppID 无需重置 AppSecret；重置密钥会影响现网登录。

**完成标志**：你能说清楚“方舟网页现在用的是哪个服务号”，且手里的管理员微信可以批准该服务号的绑定。

## 2. 把服务号绑定到微信开放平台

1. 另开标签页，打开[微信开放平台](https://open.weixin.qq.com/)，登录**以后长期管理 T方舟移动应用的那个开放平台账号**。如果团队已经创建过方舟移动应用，先选能在「管理中心 → 移动应用」看到它的账号。首次使用才注册开放平台账号，并按页面完成主体资料、管理员验证和申请能力所需的开发者资质认证。
2. 点「管理中心」，进入「公众号」或「公众号/小程序」栏目。先看已绑定列表，如果第 1 步的服务号已在这里，直接核对名称和 AppID，跳到第 3 步。
3. 点「绑定公众号」或「绑定公众号/小程序」，选公众号。按当前页面提示选择或填写第 1 步那个服务号，用它的管理员微信完成扫码确认；若平台要求主体或其他授权人验证，按提示完成。
4. 返回管理中心刷新，打开绑定详情，核对名称和 AppID。若提示“已绑定其他开放平台账号”，先找那个账号的管理员，核对它是否已经维护线上应用。不要为通过这一步直接解绑旧关系：跨开放平台账号调整，原有 UnionID 的对应关系可能变化，需要先核对现有业务。

**完成标志**：同一个开放平台账号的已绑定列表里能看到你的服务号。仅用同一部手机、同一个管理员微信或相同主体登录两个后台，并不等于已经绑定。

## 3. 在同一个开放平台账号里登记 iOS 应用

1. 留在[微信开放平台](https://open.weixin.qq.com/)，点「管理中心 → 移动应用」。先查已有的 T方舟。已有就进「查看 / 应用详情」，核对 iOS Bundle ID；没有才点「创建移动应用」。
2. 按页面填写真实应用名称 T方舟、应用简介、官网和图标，选择 iOS 平台。Bundle ID 填 `cn.tboxos.ark`，Universal Links 填 `https://tboxos.cn/wechat/`。如要求填写 Team ID，填 `8BQ285B3J2`。如果页面要求商店链接或证明材料，按实际状态走页面提供的流程；尚未上架不要编造链接。
3. 提交并回到「移动应用」列表看审核状态。审核通过后进入详情，记下**移动应用 AppID**。在该应用的「接口信息 / 权限 / 能力」里找到「微信登录」：显示已开通就继续，显示申请就提交资料并等待可用。应用审核通过与登录权限可用要分别核对。
4. 同一账号下切回第 2 步的公众号列表，再回到移动应用列表。记录两处的 AppID。移动应用 AppSecret 以后由方舟后端用于原生登录换码，按平台提供的方式安全保存。**方舟后台现有「服务号 AppSecret」保留服务号原值。**

**完成标志**：同一开放平台账号下能分别看到服务号和 T方舟移动应用，且移动应用的「微信登录」能力可用。后台菜单可能因账号权限和控制台版本变化，以登录后显示的同名能力为准。[微信移动应用登录开发指南](https://developers.weixin.qq.com/doc/oplatform/Mobile_App/WeChat_Login/Development_Guide.html)

## 4. 部署方舟后端，让数据库开始记录

1. 将本次后端代码提交并推送到 GitHub 的发布分支。
2. 打开[后端部署（PM2）](https://github.com/oukek/t-box/actions/workflows/api-pm2.yml)，点 **Run workflow**，选含本次提交的分支，勾选 **start_services**，再点 **Run workflow**。等待数据库扩展和服务健康检查均成功。仅为启用 UnionID 存储，无需重打 iOS 包。
3. 打开方舟管理后台的「微信登录」，核对服务号 AppID、前端根地址 `https://tboxos.cn` 和启用状态。如果网页授权原本就能用，保留现有值。若首次配置，请在公众平台设置网页授权域名 `tboxos.cn`，按页面要求发布校验文件，具体见[方舟微信登录配置](wechat-login.md)。
4. 用数据库管理工具连接**方舟后端实际使用的数据库**，执行下面的只读 SQL。应有一行扩展记录，并能看到 `unionid_hash`（查询用）和 `unionid_cipher`（加密保存）两列。服务号 OpenID 仍单独用于原身份识别及 JSAPI 支付。

```sql
SELECT id, completed_at FROM schema_extensions
WHERE id = '2026-11-26-wechat-union-identities';
SHOW COLUMNS FROM wechat_union_identities;
```

## 5. 在自己手机上验收服务号登录

1. 用自己的微信打开 `https://tboxos.cn/`。先记住原方舟账号中的一条待办或一本账本。如果已经登录，退出方舟后重新点「微信登录」，让方舟真正向微信发起一次授权。单纯刷新页面只会恢复方舟会话。
2. 确认登录后仍能看到刚记住的数据。用后台用户管理里这个测试用户的方舟用户 ID，替换下面的中文提示，执行只读查询。**返回一行且「已取得UnionID」为 1**，代表该方舟账号的微信身份已经补齐。查询不会输出 UnionID 或 OpenID 原文。

```sql
SELECT w.user_id, w.app_id, (u.unionid_hash IS NOT NULL) AS 已取得UnionID
FROM wechat_identities AS w
LEFT JOIN wechat_union_identities AS u
  ON u.app_id = w.app_id AND u.openid_hash = w.openid_hash
WHERE w.user_id = '替换为方舟测试用户ID';
```

3. 如果返回 **0**，先核对第 2 步绑定的 AppID、第 4 步部署的后端和本次是否真的重新授权。静默授权拿到 OpenID 时，微信未必同时返回 UnionID；方舟会保留原账号，不强制老用户每次授权头像。可另用一个首次登录方舟的测试微信，完成资料授权，再用该测试账号自己的方舟 ID 查一次。若仍为 0，优先复核绑定和微信授权权限；不要靠昵称、头像或手填字段匹配用户。若查询返回零行，先确认用户 ID 和数据库，纯密码账号没有服务号身份行。
4. 出现「微信身份关联冲突」时，保留原有数据，记录操作时间和渠道 AppID，联系运营者核对是否更换或迁移过开放平台账号。不要手工覆盖冲突记录。

## 6. 以后接通 iOS 一键微信登录时，再验收跨端

微信后台关联完成后，当前服务号可以先积累 UnionID。**本次后端改动没有新增 iOS 微信授权按钮。** 当前 `capacitor/wechat.config.json` 对接的是已有原生微信 SDK 配置。单独打开里面的开关不会实现原生登录，也无需为了收集服务号 UnionID 开通微信支付。

后续原生登录开发时，用第 3 步的移动应用 AppID、单独的服务端 AppSecret 和 `/wechat/` 回调；在已启用微信关联的主站版本发布后，访问 [AASA 文件](https://tboxos.cn/.well-known/apple-app-site-association)，确认 HTTPS 直接返回 JSON，包含 `8BQ285B3J2.cn.tboxos.ark` 和 `/wechat/*`。AASA 中仅有 `/open.html` 不能验收微信回跳。[项目原生微信配置说明](wechat-native-payments.md)

原生登录接通后，用**同一个微信**在网页和 iOS 各登录一次。再次执行第 5 步的查询：同一个方舟用户 ID 下应有两个渠道的 AppID，且两条均已取得 UnionID；两端打开的是同一本账、同一份待办。如果老账号尚未取得 UnionID，原生端首次登录需要先通过原账号验证绑定，不能凭两个不同的 OpenID 推断是同一人。
