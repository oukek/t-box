# 图片模型分辨率与调度

每个图片模型配置通过 `imageTiers` 多选支持的档位，例如 `["2k", "4k"]`，至少一项。此字段以 JSON 数组保存在 `ai_models.image_tiers`，随模型池配置版本进入 Redis 缓存。后台模型列表、编辑表单和模型池选择均显示档位。

## 配置方式

1. 在模型管理中选择服务商、上游模型和“图片生成 / 编辑”用途。
2. 按服务商实际能力勾选支持的分辨率，填写统一采购报价；各档位可额外填写独立报价（`image_prices`），未填写沿用统一报价，0 表示该档位无采购成本。模型列表接口不提供统一的分辨率能力信息，不能根据模型名称猜测，也不会因为选择 4K 就自动获得服务商的 4K 支持。
3. 将配置加入图片模型池。同一服务商的同一个上游模型只需一条配置，即可勾选多档；同一服务商、同一上游模型标识不允许重复配置。
4. 平台按用户请求档位筛选，再在同档模型中沿用负载、并发和冷却调度。例如只勾选 2K / 4K 的模型可参与这两档调度，不会承担默认 1K 请求；单档模型只承担勾选档位。

## AI 与请求规则

- 未指定或传入 `null` 时，生成与编辑均默认 1K。图片助手和图片技能均包含该规则，工具描述同步声明。
- 只有用户明确要求 2K / 4K 时升档；“高清”“精美”等形容词、较大的原图本身不触发升档。应用业务与主会话调度保持解耦。
- 找不到匹配模型时，在请求服务商及扣额度前返回 `IMAGE_TIER_UNAVAILABLE`（409），不自动跨档重试。
- 同一任务中从 1K 切换到 4K、再切回 1K 时，准备阶段按档位缓存配置，不复用错误档位的首次模型。失败的准备请求不会永久缓存。
- 1K 默认请求 `1024x1024`；平台可配置为 `1024x1536` 或 `1536x1024`。不使用服务商的 `auto` 尺寸，以免默认升档。2K / 4K 分别请求 `2048x2048` / `4096x4096`。
- 这些较高尺寸是 OpenAI 兼容服务商的能力约定，不代表所有 OpenAI 图片模型均支持。现有 SDK 的尺寸枚举之外的参数只在图片适配器边界转换类型。
- 返回图片仍检查实际尺寸；尺寸不足时不扣用户额度。模型调用审计记录实际模型、输入档位和请求尺寸；用户额度计价沿用费率快照，上游采购成本优先使用被选配置中请求档位的独立报价，缺省时使用统一报价。

## 数据库与验收

空库初始化基线为 `2026-10-23.2`。现有数据库不会通过 `db:init` 自动修改或清空，部署预检继续检查完整基线指纹。

- 单元测试：`pnpm --filter @t-box/api exec tsx --test test/image-tiers.test.ts`
- 集成测试：`pnpm --filter @t-box/api exec tsx test/image-tiers.integration.ts`

集成测试自行创建并清理随机测试库，只连接本地伪造的 Images API，验证档位持久化、单配置多选能力、分档成本报价、缓存失效、连续跨档任务、审计归属、编辑选择和无匹配模型时禁止跨档；不调用已配置的真实服务商。
