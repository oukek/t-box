# AI 资源包与实时额度计费实施规格

状态：已实现，使用新数据库基线 `2026-10-23.2`。本文是开发、测试和后续验收的依据，规则变更同步更新本文。

## 已确认规则

- 项目未上线，直接采用新的资源包与额度体系，不实现旧人民币充值、旧余额或旧费率的兼容、迁移路径。不要清空已有应用业务数据。
- 用户支付人民币购买资源包；AI 服务消耗额度；供应商成本独立记录。三者不得混用。
- 每次模型调用实时记录 usage、即时结算，不等待整轮会话完成或用户确认。调用前必须预占，输出上限与任务累计预算共同控制超额。
- 指定用户可以设置为免费用户：完整记录用量、应扣额度、供应商成本、失败和重试；不预占、不实际扣额度。仍受任务预算、并发及平台成本预算限制。模式在调用开始时固定并审计。
- 用户计价采用独立对外费率，不随供应商采购费率或折扣自动变化。标题、记忆整理、自动上下文压缩由平台承担。
- 对外额度内部精度固定为每额度 10000 个整数单位，复用 BigInt 精确计算；前端仅格式化显示，不使用浮点数计算余额。人民币订单使用整数分。
- 图片生成初始 1K/2K/4K 为 10/20/30 额度；编辑独立配置，初始同价。图片理解按会话用量计价，上传文件、本地工具及预览不消耗 AI 额度。
- 单任务默认额度上限 90；图片默认最多 3 张，均后台可配置。成功文本与图片共同计入预算；不能把三张 4K 的 90 额度之外的文本开销忽略。
- 有真实 usage 立即结算；本次调用后续被确定为协议/解析失败或明确拦截时自动冲正。未成功调用不扣用户额度，上游失败成本仍保留。部分成功按成功调用收费。重试失败不重复收费。
- 每次供应商尝试有独立记录，关联逻辑请求、任务、消息、Agent。缺失 usage 不伪造实际用量；待核对记录和预占必须可查询、处理，不能遗忘。
- 后台管理资源包、商品版本、上架状态、有效期、售价、额度、赠送、排序及公开费率；配置入 MySQL，Redis 缓存，扣费授权永远依据数据库事务。
- 支付只能由已验签回调/主动查询确认。订单冻结商品快照，支付成功与权益发放同一事务，重复回调只发放一次。
- 额度按到期时间、发放时间、ID 依次消耗，可跨包。过期检查在每次操作执行，定时扫描仅整理状态。过期后已有有限预占允许完成结算，释放时不恢复成可用额度。
- 修改商品与费率不改写历史快照。套餐下架不影响已购权益。已售商品的价格保护需要版本约束，不允许静默贬损。
- 退款对应原人民币订单，冻结/收回原订单权益，保留异步退款与失败恢复；不按内部名义金额直接退款。iOS 原生端沿用暂不开放购买的安排。
- AI 运行层和独立应用不遍历套餐，不操作额度表；统一通过平台计费接口调用。

## 数据职责和不变量

- 商品/商品版本：稳定编码、已发布快照，购买只读取已上架的版本。
- 用户额度账户：付费/免费模式、可用与预占汇总版本；不使用 Redis 批准扣款。
- 额度批次：订单/赠送/补偿来源、原始额度、剩余、预占、已消费、已过期、已收回、有效期、版本。
- 使用记录：每次实际请求的用量、应扣、实扣、上游原价与折后成本、费率与模式快照、状态、逻辑请求/重试/任务/消息/模型关联。
- 批次分摊：预占、核销、释放及冲正绑定原批次，分摊不重复存储 token 和成本。
- 额度流水：不可变事件，幂等键，发放、消费、释放、过期、收回及补偿可以核对。
- 支付订单/退款：人民币记录，关联商品版本与发放批次，和用量分开。
- 累计发放 = 可用 + 预占 + 已消费 + 已过期 + 已收回。免费使用不改变任何批次。
- 相同逻辑事件不会重复发放、重复结算、重复冲正。调用前预占必须覆盖允许的最高收费；异常超出用户授权上限由平台承担并告警。
- 网络请求不在数据库事务中等待。账号及批次锁顺序一致，多 API/worker 并发使用同一规则。

## 页面与实时通知

- AI 中心：我的额度、资源包购买、批次明细、消费记录、订单和退款。
- 后台：资源包与费率、用户额度及免费模式、使用与上游成本、订单退款。
- 调用结算后推送账户变更；断线/漏事件后读取数据库快照。消息时间线继续显示处理时长，不恢复大段 token 统计。
- 失败调用与自动冲正显示明确状态，用户明细不暴露服务商、底层模型或采购成本。
