# 退款与渠道对账

管理后台「支付订单」新增退款记录与每日渠道对账。只接受管理员登录及 CSRF 保护的操作；前端用户支付成功提示、二维码、客户端回执都不能作为入账/退款成功依据。

## 全额原路退款

当前支持对一笔已支付充值单做全额退款：微信退回原实付金额，本地收回该充值到账额度和原赠送额度。例如实付 100、赠送 10，退款金额 100 元，钱包需要收回 110 元；可用余额不足 110 时拒绝申请，不允许制造负余额或只收回实付部分。

申请先在钱包事务内预留需收回额度，持久保存原退款 ID、原支付流水、商户配置和原因，随后请求微信退款。并发/重试沿用同一请求键；结果未知继续查同一退款单，不生成新退款 ID。微信可信查单/验签解密通知确认 SUCCESS 后，在一个本地事务中解除预留、扣回额度、写唯一退款流水；CLOSED 释放预留，ABNORMAL 或未知结果继续保留等待核对。经可信查询确定原单不存在时，可用同一不可变微信退款单号重新提交。

关闭新的充值通道不影响旧订单退款、查单及通知；退款绑定原商户配置，凭据轮换不能把旧订单迁移到另一商户。旧支付成功通知重复到达，不会让已退款订单再次入账。后台不提供“标记退款成功”或编辑财务流水的捷径。当前没有部分退款、提现或自动退还已消耗额度。

退款通知地址为 `/api/v1/payments/webhooks/wechat/refunds`，必须对外配置 HTTPS，并保留原商户的有效验签/解密凭据。应用重启后按持久租约继续查询未确认退款。

## 每日渠道对账

每天北京时间 11 点后，后台自动补查近 7 天的商户交易账单；每分钟最多处理 5 份。失败保留简短原因，间隔约一小时重试，最多 8 次自动尝试；管理员也可手动选择近 90 天内、今天之前的日期核对。任务按「商户 + 日期」唯一，配置轮换不会重复建同商户同日的对账任务。

通过验签后的账单元数据取得 SHA1 与下载地址，仅允许微信固定 HTTPS 来源；下载文件校验完整 SHA1 后才解析。此文件下载响应按微信两步协议使用元数据摘要验证，不错误要求文件本身带普通 JSON 响应签名。CSV 严格处理引号、反引号 ID、金额精度、币种、商户及重复流水，不保存商品描述和客户字段。

核对本地支付/退款流水、金额和状态，记录 local_only、remote_only、金额/流水/状态冲突等差异。每份记录保存总差异数及前 500 条详情，**不会从 CSV 直接增减用户余额**。需要进一步入账时，走原支付/退款的可信单笔查询链路。当前核对交易账单，不包含商户资金账单、手续费或发票。

## 验收范围

真实 MySQL + 本地微信替身已覆盖退款并发幂等、赠送回收、余额不足、伪造金额/商户、迟到通知、丢响应后恢复、账单差异和账务不被对账修改。加密通知、签名、下载来源与文件摘要有独立测试。

真实商户扣款/退款、微信后台账单可用性和原生设备回调仍需商户配置与测试设备；当前未执行真实资金交易。上线前至少验证一笔小额充值→重复查单→全额退款→通知重放→次日对账，并核对微信与本地总账。
