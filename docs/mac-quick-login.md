# Mac 版账号快捷登录

网页登录弹窗和采集插件的官方授权窗口均提供 Mac 账号入口。Mac 必须运行并保持有效登录；首次使用需允许浏览器连接本机应用，已授权后自动识别，用户点击账号按钮才签发新会话。普通用户账号密码入口已隐藏。默认显示二维码；识别成功后以头像、昵称和快捷登录替换二维码，选择其他账号返回扫码。插件使用主站授权窗口连接本机，不向店小秘页面授予本机网络访问或暴露账号凭据。

## 通信与会话

- Tauri 主窗口在服务端核实账号后，通过受主窗口随机密钥和 capability 限制的 `desktop_login_identity` 命令同步会话。Rust 仅在内存保存 Token，退出或切换账号时清理旧识别挑战。
- 原生服务固定监听 `127.0.0.1:17436`，不监听局域网；端口被占用不阻塞 Mac 主界面，但快捷登录不可用。正式版本只接受 `Origin: https://tboxos.cn`、精确 Host 和自定义 `X-Tbox-Login` 请求头，支持 CORS/PNA 预检。开发构建额外允许主站本地 5173 端口。
- `/v1/account` 使用 Mac 当前会话请求官方 API `/auth/me`，只返回账号摘要和 90 秒、单次的挑战。无有效登录、断网或账号切换均不使用缓存头像冒充已登录。
- 浏览器/插件先向 API `/auth/handoff/start` 创建 2 分钟随机凭据；用户点击后通过 `/v1/approve` 请求原生服务批准。原生服务只向固定官方 API `/auth/handoff/approve` 发送 Mac Token，HTTP 响应不包含 Token。
- `/auth/handoff/redeem` 在事务锁下核对随机凭据、目标客户端、预期账号及 Mac 会话是否仍有效，签发独立设备会话（网页/插件 7 天，PWA 30 天，均活跃续期）并标记已消费。批准阶段不提前签发会话。会话名称区分浏览器和采集插件，退出某一端不撤销其他端。
- 插件通过已绑定的官方授权窗口、标签页和 nonce 发起及完成 Mac 交接；新 Token 由扩展后台领取并保存，主站不会被切换账号。切换为 Mac 登录后不再接受旧的扫码流程回调。微信扫码配置不可用时仍可使用 Mac 登录。

账号密码和微信账号均可使用，不依赖微信配置开启。商品数据的上传、认领与持久化不在此功能范围内。

## 浏览器权限

前端查询 `loopback-network` 权限；已允许时自动识别，首次需授权时提供“使用 Mac 账号”入口，拒绝时继续显示二维码。对不支持权限查询的浏览器，首次点击成功后仅记录“允许尝试识别”的偏好，下次自动尝试，不缓存账号作为认证依据。请求声明 `targetAddressSpace: 'loopback'`，超时、拒绝和连接失败不显示检测提示，不干扰扫码。不扫描其他端口，不绕过浏览器权限。

依据：[Chrome 本地网络访问文档](https://developer.chrome.com/docs/modern-web-guidance/guides/security/local-network-access)。如果站点额外配置了 CSP，`connect-src` 需允许 `http://127.0.0.1:17436`；如果设置了 Permissions-Policy，不能禁用本站的 `loopback-network` 权限。其他浏览器可能不支持此连接方式，保留扫码登录。

## 发布顺序

1. **提交并推送代码及版本文件。** 后续工作流使用包含本次改动的同一提交。版本预留会校验线上基线；若目标版本已被占用，先核对已登记构建，不能覆盖同版本的不同内容。
2. **先运行「后端部署（PM2）」。** 勾选 `start_services`，等健康检查通过。现有启动流程会运行数据库初始化/扩展步骤，新增 `2026-11-26-login-handoffs` / `login_handoffs`，无需手动建表。只有普通 ID、哈希和过期索引，无新增外键或数据库级联约束。此次后端还包含微信插件授权与活跃续期，必须先于客户端上线。
3. **运行一次「macOS 整包发布（内置本次界面）」。** 使用本次提交，构建 UI `1.3.4` 和核心 `1.0.4`。该流程完成双架构安装包的签名、公证，并登记同批网页/PWA 与 Mac 候选。不要再单独运行「主界面构建（网页、PWA、Mac）」占用同一 UI 版本。仅更新 UI 无法让旧 Mac 核心提供本机授权服务。
4. **体验候选，再统一发布。** 在后台「应用管理 → 系统发布 → 桌面端」下载本次体验版，核对 UI `1.3.4`、核心 `1.0.4`，验证登录与退出。之后到「主界面」找到同一批次候选，填写更新说明并审核发布。本次没有后台代码变更，已有上述发布页面时无需重复部署管理后台。
5. **核对网页和 Mac 更新。** 主站 `/web-version.json` 应为 `1.3.4` 且构建编号对应本次候选；Mac 在「设置 → 系统版本」检查更新，完成核心和界面升级并重启。旧 Mac 核心不提供快捷登录，网页继续使用浏览器账号或扫码回退。PWA 更新后因独立登录存储需要重新登录一次。
6. **最后分发插件 `0.3.5`。** 安装包为 `output/collector-releases/tark-collector-0.3.5.zip`。解压并重新加载扩展，刷新主站和店小秘页面，验证 Mac → 浏览器账号 → 二维码的优先级、选择其他账号及退出。商品上传、认领仍不包含在此次发布中。

工作流入口：[后端部署（PM2）](../.github/workflows/api-pm2.yml)、[macOS 整包发布](../.github/workflows/desktop-release.yml)。本次操作单替代旧版 iOS 发包文档中的网页/Mac 示例版本；不需要运行 iOS 发包。

可用于后台的更新说明：

- 支持通过本机 Mac 已登录账号快捷登录网页和采集插件，展示头像与昵称。
- 插件优先识别 Mac，其次识别浏览器账号，未识别到时使用二维码。
- 隐藏账号密码入口，支持选择其他账号与退出。
- 网页和插件采用 7 天活跃续期，PWA 和 Mac 采用 30 天活跃续期。


没有新增生产环境变量或外部依赖。正式原生桥接固定使用 `https://api.tboxos.cn/api/v1`；开发构建额外允许 `http://127.0.0.1:6868/api/v1`。更改生产域名需同步原生 Origin/API 白名单。

## 验证范围

已覆盖后端一次性消费、账号/目标绑定、源会话撤销、过期及并发模拟；插件窗口绑定、Mac 交接、拒绝旧扫码回调，以及微信配置关闭时仍可打开授权窗口；原生 HTTP Origin/Host/自定义请求头、预检、挑战复用与 Token 不外传；浏览器交接、拒绝访问和取消后的禁止领取。后端测试使用内存仓储替身，原生测试使用真实 loopback HTTP 与模拟官方 API。

生产构建、类型检查和模拟页面检查不代表真实签名 Mac 安装包、线上数据库及所有浏览器权限弹窗已验收。上线后需使用真实账号确认：第一次授权、再次自动识别、Mac 切换/退出、浏览器退出后重新快捷登录、插件切换和拒绝本机访问时的扫码回退。

网页登录及插件会话采用 7 天滚动有效期，安装的 PWA 与 Mac 客户端采用 30 天。有效认证请求触发续期，写入按 5 分钟节流；过期、撤销或禁用账号不能恢复。原生快捷指令凭据仍保持原固定期限并依赖父会话。二维码仍为 5 分钟。

客户端通过 X-Tbox-Client 标识登录来源，服务器将类型前缀保存在设备名称中，微信扫码父流程也保留原客户端类型，续期根据已存类型判断。Mac 浏览器属于网页。旧有效 Mac 会话在新版客户端校验账号时升级至 30 天。PWA 使用独立令牌存储，更新后需重新登录一次，避免与普通网页共享期限。

插件授权页按 Mac → 浏览器 → 二维码检测。无 Mac 或本机权限不可用均静默回退；用户主动选择二维码后，异步检测不得覆盖选择。
