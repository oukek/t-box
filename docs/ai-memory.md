# AI 记忆

记忆由 AI 宿主管理，应用仍通过工具提供数据和权限。会话压缩缩短当前模型输入；跨会话记忆保存用户确认的信息；任务工作状态跟随执行检查点保存。这三者独立。

## 用户入口

「AI 中心 → 记忆」支持添加、修改、搜索、确认建议、删除和清空，编辑使用弹窗。每条记录包含类型、有效期、版本及来源摘录。删除对话或修改/删除来源消息会使由它产生的记忆失效；手工添加或手工修正的信息独立保留。

「使用记忆」控制账号的读取和写入。「自动整理建议」默认关闭，开启后只处理新产生且完成回答的普通文字消息，不回填旧历史。自动整理仅生成待确认建议，确认前不送给模型。自动阶段目标最多保留 90 天，从来源消息时间计算；过期不再召回。

会话顶部不再提供单独的记忆开关，统一在「AI 中心 → 记忆」管理。账号的「使用记忆」控制读取与写入；关闭不会抹去模型已看到的旧聊天内容，需要隔离旧上下文时应新建对话。

明确要求「记住」或「忘记」时，模型可调用 `memory_remember` / `memory_forget`，经前端弹窗确认后才执行。确认沿用私有交互协议，断线或任务恢复后重新询问，旧同意不能授权新操作。`memory_search` 只返回有效条目的引用，正文在下次模型请求前重新校验，不把整份记忆写进工具历史。

## 存储与调用

- MySQL：`ai_memory_states` 保存账号开关、版本和失效代数；`ai_memories` 保存记忆与候选；`ai_memory_sources` 保存来源和内容指纹；`ai_memory_jobs` 保存后台任务、租约和模型请求检查点。
- Redis：用户 ID / revision 独立缓存键，60 秒过期。每次读取仍从数据库验证开关、归属、来源、有效期和最新 revision；缓存故障回源数据库。修改和忘记推进版本，旧缓存不会用于新请求。
- 工作状态：`AgentFrame.workingMemory` 保存目标、阶段、计划、已完成回执 ID 和待处理调用。成功依据真实回执，不依据模型自述。不额外调用模型生成工作状态。
- 召回：按偏好及请求相关度选择，最多 12 条，默认参考预算 1600 token，仍受总上下文预算约束；正文仅临时注入本轮，不写回持久模型历史。专业 Agent 不自动获得全量记忆，主助手通过具体子任务传递必要信息。

当前使用结构化字段和中文双字/英文词检索，尚未接入向量数据库或 embedding，不能保证覆盖所有同义说法。账单、宝宝档案、共享资料和实时状态应查询对应应用，不复制为通用记忆。

## 后台整理与配置

API 内置 worker 或独立 `t-box-worker` 每 10 秒扫描；每个进程串行处理，多进程通过数据库租约竞争。正常回答不等待整理，简单问答不会增加前置分析或额外回复阶段。

只处理用户原文，排除有附件、应用选择、受保护资源或授权绑定的会话。自动候选限定为个人偏好和有期限的目标，忽略他人信息、应用事实、凭据和系统指令。单条超过 8000 字不截断提取。结构和敏感内容校验只是防线，语义判断由模型完成，用户确认才生效。

任务固定模型配置、prompt、相关记忆索引和来源指纹。可恢复错误最多自动重试 5 次，恢复不重置次数，不执行应用工具。关闭、修改来源或忘记会取消旧任务。忘记还推进来源时间边界，旧消息复制到新分支也不会重新提取。忘记后保留无正文的消息指纹防重，防止同一旧来源再次保存时复活；删除整个对话会清理标记。

在后台「AI 配置 → AI 记忆」配置总开关、提取 prompt、模型（普通会话池或池内指定模型）、召回 token、数量上限、输出预算和超时。配置入数据库并复用 Redis 版本缓存，不使用 env。模型审计用途为「记忆整理」，独立记录实际请求、用量、重试和失败。费用由平台承担，不扣用户余额；缺失 usage 保留待核对记录。

## 升级与验证

空库执行 `pnpm db:init`。当前资源包体系采用新基线 `2026-10-23.2`，旧资金结构不做兼容，请配置新数据库初始化，原有数据不自动删除。记忆整理成本由平台承担，免费用户与收费用户均不扣记忆整理额度。数据库流程见 [初始化说明](database-initialization.md)。
