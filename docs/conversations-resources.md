# 会话、图片工具与私有资源

默认入口始终是普通会话模型。看图是普通会话模型的图片输入能力；生成、编辑图片是独立工具，不应根据“用户上传了图片”就自动开启图片生成。

## 模型配置

后台「模型」管理两类模型：

- 普通会话：配置选择 Responses 或 Chat Completions API、流式响应、多轮工具调用；支持图片输入的模型需勾选「支持图片输入（看图）」。
- 图片生成 / 编辑：Images API 的 `/images/generations`、`/images/edits`。在「图片生成与编辑工具」独立选择，与普通模型可关联不同服务商。

用途、看图能力、两个运行时选择均存储在 MySQL；服务商密钥沿用服务端加密存储。`/models` 发现接口只提供模型名称，不能推断能力或兼容性。当前使用通用参数 `n=1`、`size=1024x1024`，生成和编辑均兼容 `b64_json` 或图片 URL；DALL-E 生成请求显式选择 base64，其他模型不强加可能不支持的 `response_format`。URL 由后端下载后存入用户私有资源，不直接暴露为前端图片地址。下载仅允许标准 HTTPS 公网地址，逐跳检查 DNS 并固定连接 IP，最多 3 次重定向、30 秒、10 MB，不携带服务商密钥；实际文件内容仍须通过图片类型校验。配置图片模型不代表供应商自动兼容；真实供应商需要验证生成和编辑两条接口。

普通会话配置在每次用户任务开始时取一次快照；图片配置在本轮首次调用图片工具时取一次快照。运行中的循环保持一致配置。普通模型通过 `skill_activate(image_processing)` 获取 `images_generate`、`images_edit` 的 schema，再执行工具；编辑只能引用当前会话已附加或生成的、属于当前账号的图片。服务商请求由后端 `openai` 库发起，前端不接触密钥。

图片生成可能收费。上传、预览和模型配置保存不会自动生成图片。相同任务内重复图片工具参数会复用结果；失败也不会自动重试。前端断线后后端仍继续执行，遇到必须由前端处理的步骤才暂停；取消、执行超时或服务重启后不自动重试未完成的调用，已生成的资源会保留。

## 数据和存储边界

- `resources`：账号、文件名、真实 MIME、大小、上传/生成来源、创建与删除时间。
- `conversations`：账号、标题、可见消息、模型输入、工具回执和请求去重状态、涉及的通用应用资源引用（`appId/resourceType/resourceId`）、更新时间。
- 文件存于 `api/.storage/resources/<uuid>`，权限 0600；目录 0700，默认已忽略。备份必须同时包含数据库、私有文件和服务商密钥加密用的 vault key。当前单机开发可用，部署多实例时需要替换为私有对象存储，并把会话所有权/任务去重搬到可共享的持久存储。

资源仅允许所属账号经 Bearer 认证读取。页面通过认证请求取 Blob，再生成本地预览 URL；没有把 token 放到查询参数，也没有公开可枚举的静态资源目录。下载设置 `private, no-store`、`nosniff`，文本/PDF 强制附件下载。MIME 依据文件内容识别，不相信扩展名；当前允许 PNG、JPEG、WebP、PDF、UTF-8 文本。

每个文件最多 10 MB；每条消息最多 4 个文件、合计 20 MB；每个账号最多 500 个文件、300 MB。模型本轮优先保留最近的图片，图片总输入最多 20 MB；文本文件每个截取最多 100000 字符，总共最多 256000 字符。PDF 目前支持上传、保管和下载，尚未实现 PDF 内容提取，模型会得到明确提示，不能声称已经读过 PDF。

会话消息和数据库只保存 `asset:<id>` / `asset-text:<id>` 引用及资源元数据。调用模型时后端再次核对资源所有权，临时解析为图片 base64 或文本，删除的资源变为不可访问提示。用户文本、文件内容和供应商返回的内容都不作为程序权限依据。

首页通过左侧栏查看、继续和删除历史，暂显示最近 100 段；没有历史时隐藏历史入口，当前没有消息时隐藏新建对话入口。侧栏支持 Esc、关闭按钮和点击遮罩关闭，并恢复焦点。删除会话不会删除其中已经创建的账单和资源。删除资源会让会话附件无法读取。WebSocket 内存 session 只是运输连接，数据库 archive 是持久历史；服务重启后可按 conversation ID 恢复，不自动重放写入。请求 ID 与调用 ID/结果会一同恢复用于去重。恢复中断任务时保留可见结果并标记任务中断。

## 私有授权与模型工具隔离

本项目的前端与 API 使用同一个登录体系，直接使用服务端授权记录比向模型传一个新 token 更简单，也更易于立即撤销。

1. 应用工具声明所需资源引用和 `read` / `write` action，通用执行器交给对应应用权限适配器检查。
2. 后端确认当前用户确实是账本成员、有相应角色权限；账本密码授权不足时，发送私有 `application_authorize` WS 事件给当前连接。此事件不暴露为大模型工具。
3. 前端弹窗显示具体账本、用途、范围和 10 分钟期限。只读授权默认只读，有写入权限的用户可以主动勾选同时授权写入。
4. 密码仅经 `POST /ledgers/:id/unlock` 提交；后端验证 scrypt 摘要，保存绑定账本、登录 session hash、密码版本、范围、固定到期时间的授权。只读授权不能写入；读写授权包含读取；授权不能提升成员角色。
5. 前端 WS 回执只发送 `{authorized:true/false}`。回执不能代替权限：后端在继续时、工具调用时、实际数据库事务中再次核对授权。密码、原始登录 token、授权记录不进入工具参数、模型上下文或会话历史。
6. 改密码、锁定、退出登录、账号禁用或成员移除即时使授权失效；10 分钟内实际操作不会滚动延长权限。

已有财务工具会把对应消息标记为受保护账本内容。历史列表隐藏失去权限或仍锁定会话的标题；打开、恢复和继续时检查所有涉及账本。继续已有会话前需要重新授权过期的账本，授权失败不会将历史财务内容发给模型。单独移除共享成员不会复制财务记录给退出的成员。

未来如果独立服务需要调用受保护应用，可在相同边界增加服务端 opaque capability token，绑定账号、resource ID、action、有效期、受众和撤销状态；仍由可信后端持有，不把它交给模型。新增应用注册自己的私有客户端能力、权限适配器和授权界面，复用通用交互/注册流程，不应让模型决定权限范围或接收密码。

## 接口与验证

- `POST /resources`：带认证的二进制上传，`Content-Type: application/octet-stream`，文件名在 `X-File-Name` 编码传递。
- `GET /resources?page=1&source=uploaded|generated&kind=image|file`：每页 24 条。
- `GET /resources/:id/content`、`DELETE /resources/:id`：私有读取、删除。
- `GET /conversations`、`GET /conversations/:id`、`DELETE /conversations/:id`：列表、打开前权限检查、删除。
- WS `message.send.scopeBindings`：应用资源作用域；`message.send.attachmentIds`：资源 ID 数组；`session.open.conversationId`：恢复持久会话。
- 后台 `PATCH /admin/settings`：`modelId` 与 `imageModelId` 可独立更新，对用途和启用状态做校验。

运行 `pnpm test:media` 验证真实 MySQL 和私有文件、HTTP 上传下载、持久历史和去重、模拟 Images API 的生成/编辑、图片工具循环与重复调用、10 分钟范围授权、伪造 ACK、密码隔离、受保护历史的成员权限。测试创建并清理自己的账号、账本、会话和资源文件，不访问真实收费供应商。`pnpm test:admin` 验证两类模型的独立选择和配置保护。

官方接口参考：[图片输入](https://developers.openai.com/api/docs/guides/images-vision)、[图片生成与编辑](https://developers.openai.com/api/docs/guides/image-generation)。

### 个人资料

`PATCH /api/v1/auth/me` 仅接受 `{nickname}`，修改当前认证账号的昵称（去首尾空白后 1–40 字符），不接受账号 ID、用户名、密码或权限等字段。昵称保存到 `app_users`，不更换登录 token；客户端同步更新个人中心与账号设置，后续登录、成员查询会读取新的昵称。运行 `pnpm test:identity` 检查持久化、账号隔离、输入校验和失效 session。

## 多设备同步

同一账号可以在电脑和手机同时打开同一会话，各设备独立维护运输连接。打开历史立即读取数据库归档，不要求原设备断开。当前会话订阅归档变化：API 本进程提交后合并短时间内通知并通过 Socket 推送授权快照，独立 worker / 其他进程提交由每两秒一次的集中数据库版本检查发现并推送；客户端不需要轮询或手工刷新。消息在归档提交后同步，任务状态、标题及删除也自动同步，不承诺逐 token 镜像另一设备的临时流。每 15 秒心跳保留认证与丢通知恢复检查。

每个设备独立验证账号及资源授权，不广播包含受保护资源的原始消息流，也不把写入设备的临时授权交给另一设备。数据库任务租约继续约束同一会话的并行写入；正在另一设备执行的任务会显示进行中，完成后自动显示归档结果。刷新与用户命令串行，避免心跳覆盖正在提交的操作。
