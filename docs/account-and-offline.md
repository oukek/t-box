# 账号、通知与离线边界

## 账号安全

设置 → 个人信息与账号安全新增「登录设备」「账号恢复码」。设备记录返回不透明 session ID、设备名称、创建/活跃时间和是否当前设备，不返回 token 哈希、IP 或原始 User-Agent。退出其他设备在服务端撤销登录；依赖该登录的自动恢复任务也不能继续执行。最近活跃时间约每 5 分钟写入一次，最多显示最近 100 个有效会话。

恢复码需要输入当前密码生成，共 8 个一次性随机码，只显示一次，服务端仅保存 SHA-256。重新生成会让旧码失效。登录页「忘记密码？使用恢复码」以账号、恢复码和新密码重置；密码至少 6 字符。消费恢复码、更新密码和撤销全部旧登录在同一事务内执行；并发提交只有一个成功。没有保存恢复码时不能绕过账号所有权验证。恢复码不可交给 AI、客服聊天或其他人。

启动时遇到暂时网络/服务错误会保留登录凭据，最多自动重试 5 次（1/2/4/8/16 秒）；恢复网络也会重新尝试。明确 401 才清除失效登录。迟到响应不会覆盖已切换的账号。不会把离线缓存的用户资料当作服务端认证结果。

## 持久通知

AI 中心 → 通知显示任务完成、等待前端、暂停、待核对的状态。后台约每 30 秒扫描已提交状态，读取通知时也补投递；通知以「任务 + 状态」唯一键去重，进程重启、重复扫描不会重复新增。自动恢复中的短暂停顿不要求用户干预，不生成暂停通知。迁移时记录水位，不批量推送历史旧任务。

通知只含状态和任务引用，不放会话标题、正文、工具参数、金额、密码或资源内容。打开任务仍经原权限和密码授权流程。支持单条/全部已读、按账号隔离；删除任务同时删除通知引用。接口为 `GET /notifications`、`PATCH /notifications/:id/read`、`PATCH /notifications/read`，均需要登录并禁止 HTTP 缓存。

当前这是可靠的**站内通知**。日历和倒计时继续支持原生本地通知；关闭所有页面后新产生的远程任务通知，尚不通过 APNs/FCM 送到系统通知栏。这一步需要设备注册、用户通知许可、平台凭据和真机验收，不能将站内通知描述为已完成原生远程推送。

服务号模板消息、客服消息、公众号关注事件接收同样尚未实现。后台已有服务号 AppID/AppSecret 用于支付网页授权，不会自动将站内通知发送到微信。相关凭据、用途与未实现边界见 [首次部署：微信配置](first-deployment.md#6-微信配置)。

## 经过校验的静态缓存

生产构建为宿主、计算器、记账、日历、时间生成 `tbox-offline.js` 和 `tbox-offline-sw.js`。Worker 按版本记录静态文件 SHA-256，所有文件校验通过才完成安装；下载中断或字节不符会删除未完成的新缓存，保留原版本。新 Worker 不强制接管运行中的页面，每个作用域保留当前与前一个缓存版本。开发 Vite/HMR 不注册 Worker；原生宿主优先使用打包在安装包内的资源。

只缓存构建清单中的公开静态资源。API、登录响应、消息、账单、文件下载、支付、SDK 请求及写入均不缓存。页面显示离线提示；新启动时无法在线认证就不能以缓存身份打开受保护应用。已打开应用可继续显示内存内容，但不能承诺业务操作离线提交。需要真正离线记账时，应另做加密本地库、操作日志和冲突合并，不能用重试 POST 冒充离线同步。

缓存受浏览器容量、第三方 iframe 策略和系统回收约束，不能保证长期保留。卸载应用会撤销平台权限，公开静态资源可能由浏览器继续保留；它们不包含用户资源。发布静态站点时，宿主的未版本化 `index.html`、`tbox-offline.js`、`tbox-offline-sw.js` 使用 `Cache-Control: no-cache`；带摘要的应用产物可继续 immutable。应用静态来源需要允许自身 Worker 与自身静态读取，仍不能与 API/宿主同源承载第三方代码。

本地已用构建产物完成断网重载检查。`test:operations` 验证损坏文件、旧版本保留和 API 排除；手动 代码检查与测试 中的浏览器测试在桌面与移动尺寸验证相同流程。

## 资源存储

我的资源显示当前文件数、字节与容量，默认 500 个文件、合计 300 MB、单文件 10 MB。`ResourceStorage` 端口提供 write/read/remove，删除必须幂等；每份资源入库记录不可变的 `storage_backend` 和相对 `object_path`，切换默认后端仍按旧 ID 读取旧文件，不能直接修改 ID 指向另一个空存储。

删除先写墓碑；物理删除失败保留记录，由清理扫描重试，不扫描并删除未确认归属的文件。不存在原后端时明确返回存储不可用，不伪装为资源不存在。生产文件、AI 图片、记账附件和分类图标统一上传 `tboxos/uploads/resources/`，对象均为 `public-read`，前端用公开域名和相对路径直接读取，不申请下载签名。文件列表、上传、删除与账本业务接口仍校验身份；公开链接持有者可直接读取图片或文件。生产不再使用本地后端，旧文件先通过迁移工具上传并校验后删除；本地开发未配置 OSS 时仍使用开发目录；远端对象备份需另行保留，具体配置见 [首次部署](first-deployment.md)。
