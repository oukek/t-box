## 当前执行约束

- 集成测试总入口要求显式的 `MYSQL_DATABASE=t_box_ci` 或 `t_box_test_<name>`，禁止误用个人或线上数据库；测试服务商与支付使用本地替身。
- 有共享配置的集成套件串行运行，避免测试相互覆盖服务商、默认模型和定价。
- 自动续办不能将服务商错误、等待用户输入或结果不确定的写入当作“重启恢复”无限重试。
- 生产恢复必须先验证备份并在隔离目标演练，不直接覆盖运行中的环境。
- 原生推送及微信真实扣款/退款的最终验收需要平台账号、证书与真实测试设备，不能用模拟测试声称联调完成。

## 验收入口

- `pnpm check`：格式、应用边界、生成文件一致性与所有 workspace 类型检查。
- `pnpm build`：宿主、后台、API、contracts/server 与全部可构建应用。
- `pnpm test:unit`：API、UI、SDK、原生脚本与应用发布脚本测试。
- `pnpm test:operations`：加密备份/篡改检测、静态缓存/私有请求排除、仅手动工作流、隔离库保护与真实应用脚手架编译。
- `MYSQL_DATABASE=t_box_test_acceptance pnpm db:init` 后运行同库 `pnpm test:integration`：串行运行所有数据库集成套件，拒绝隐式选择个人/线上库。
- 手动 `代码检查与测试` 工作流：另含 MySQL 导出恢复演练和 Chromium 桌面/移动验收；浏览器失败保存截图与 trace。

本轮 39 个集成套件均已在本地验证：串行入口通过 38 个，备份套件首次因 PATH 中没有 mysqldump 跳过，随后找到已安装的 MySQL 8.4 客户端，并通过完整导出/加密/新库恢复演练。CI 缺少客户端则失败。不得把“测试代码已加入”表述为“GitHub Actions 已运行通过”。
