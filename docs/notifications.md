# 系统通知中心

桌面右上角铃铛和「AI 中心 → 通知」打开同一个账号级通知面板。桌面显示未读角标；手机使用全屏抽屉。支持全部／未读筛选、游标分页、单条已读、标为未读、全部已读与消息详情。在线收到新消息时显示可关闭的全局提示；首次载入和历史消息不弹出，日历／倒计时沿用现有提醒条避免重复。消息可以使用普通、成功、警告、待处理、图片五种样式，最多三个导航按钮。图片仅在打开详情时经账号鉴权读取，不把原图预加载进列表。

已读表示看过消息，不能作为关联业务操作的完成凭据。通知按钮只导航，不能直接执行删除、支付、授权或写入。目标支持注册应用及页面参数、精确任务、受控系统页面；不接受任意 URL、HTML、脚本或设备命令。任务通知不包含对话标题、正文、财务金额、工具参数或解锁凭据，打开任务会话仍检查成员权限与资源密码。跳转目标被删除、不可访问或当前对话正忙时，界面保留通知并显示原因。

## 来源与接入

- 普通 AI 任务的完成、等待交互、暂停、待核对及图片生成结果仅留在 AI 对话与任务记录，不自动生成系统消息、不增加铃铛未读数、不弹全局提示。收起 AI 后出现完成或需处理状态时，AI 入口显示新进展标记，打开 AI 后清除；首次载入的历史完成记录不制造新标记。
- 通知按业务事件决定：AI 创建日程的成功结果留在对话，到时间的日历提醒仍进入系统通知。跨设备待办、共享邀请和其他明确业务通知可继续通过通用发布接口接入。图片样式仍支持业务消息，但资源入库不再自动投递生图成功消息。
- 用户明确订阅某次任务的完成提醒时，后端可发布独立的业务消息（例如 `task.requested`）；当前没有新增自然语言订阅识别或自动订阅入口。
- 日历和倒计时提醒在打开通知、重新联网及在线客户端的服务端扫描时收集。账号扫描位置持久保存，最多补查最近七天，沿用业务应用现有的提醒数量上限；这不是全天候远程提醒服务。点击已有网页提醒条或新安排的本地系统通知时，会尝试将对应站内提醒标为已读。离线点击或旧版系统通知缺少提醒标识时，不伪造已读成功。
- 其他可信后端通过 `NotificationService.publish(userId, sourceAppId, sourceKey, content, kind)` 接入。相同账号、来源应用及 `sourceKey` 唯一，通知正文不可用同一键覆盖，避免网络重试复活已读消息。
- 本地注册的应用 AI 后端处理器可使用宿主注入的 `ctx.notifications?.publish(sourceKey, content, kind)`。账号和应用来源由宿主绑定，不能传入其他收件人。这不是一个供模型调用的发消息工具，也不向网页提供任意创建通知的接口。

```ts
await ctx.notifications?.publish(`event:${event.id}:${event.revision}`, {
  style: 'action',
  title: '日程有待处理的操作',
  body: '打开日历查看详情。',
  actions: [{
    label: '查看日程',
    target: { type: 'application', appId: 'calendar', params: { eventId: event.id } },
  }],
}, 'calendar.action')
```

通知只展示和定位已有业务，当前没有新增「网页请求、手机接续添加系统日历」操作队列。接入该业务时仍须实现设备选择、操作持久化、实际执行及回执，不能凭消息已读认定已经写入系统日历。

## 通信与存储

- `GET /notifications?filter=all|unread&cursor=...`：每页 30 条，全账号未读数和下一页游标；按照创建时间、ID 稳定排序。
- `PATCH /notifications/:id/read`：默认已读；请求体 `{ "read": false }` 标为未读。
- `PATCH /notifications/read`：全部已读。
- `PATCH /notifications/reminders/read`：请求体 `{ "key": "业务提醒标识" }`，只确认当前账号对应提醒。
- `/notifications/ws`：与现有平台 Socket 相同的首帧登录、来源校验、心跳及撤销检查。每五秒扫描跨进程数据库状态，只发送失效提示，不推送消息正文。客户端随后拉取自己的列表；重连、恢复前台和断流时有 HTTP 补偿。

增量扩展 `2026-11-02.system-notifications` 新增 `system_notifications` 和 `system_notification_cursors`。新表只使用普通 ID 与索引，无外键与级联。任务／用户删除后的引用由业务层回收。历史 `user_notifications` 留在冻结基线中，不再导入任务通知。旧版自动投递的任务状态与生图结果从系统通知表清理，列表、未读数和更新指纹同时排除这些旧消息；对话、任务、图片和业务消息及其已读记录保留。新业务消息写入新表。不修改已发布基线指纹，不清库。

发布时先运行现有 `pnpm db:init`／后端发布初始化，再发布主站；原生端重新打包后带上新前端。没有新增环境变量、推送证书或第三方服务。当前不包含 APNs／FCM／Web Push：App 关闭时只会收到此前已经安排的本地日历／倒计时通知，通用站内消息在重新打开后读取。

验证：`pnpm --filter @t-box/api exec tsx test/system-notifications.integration.ts` 自动创建并删除独立临时数据库，覆盖增量初始化、AI 活动静默、旧自动消息清理、业务消息保留、去重、分页、账号隔离、图片权限、提醒接入、HTTP 与 Socket 更新；不改开发业务库，不调用模型或支付。另有 `test/notification-contracts.test.ts` 检查通知内容和跳转目标边界。
