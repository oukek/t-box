# 微信登录与网页支付配置

普通用户只使用微信登录，但进入网站不要求登录：日历、时间、计算器等本地工具可以直接使用，微信内也不自动跳转授权。AI、余额、个人资料等需要账号的页面显示登录入口，用户点击后才打开可关闭的登录弹窗。

主动发起登录后，微信内先静默识别身份，返回本站后提示获取昵称和头像；用户点击“授权昵称和头像，继续登录”才发起资料授权并完成登录。微信外显示二维码，手机微信依次完成静默识别、资料授权、确认登录原设备。全程不收集手机号，没有短信验证码、注册表单、账号密码登录或密码找回。管理员仍在 `admin.tboxos.cn` 使用独立管理员账号。

普通用户 HTTP、Socket 和原生快捷指令均核对当前公众号下的微信身份映射。历史密码账号的有效 Token 不能继续访问云端业务；前端升级时清除旧登录存储，重新进入微信授权，不迁移或删除旧账号数据。已经完成微信登录的新会话可以正常恢复，不会每次刷新都重复授权。

第一步使用 `snsapi_base`，服务端只取得 OpenID，不调用用户资料接口、不创建本站账号、不签发登录会话。第二步由用户主动点击后使用 `snsapi_userinfo`；服务端核对两次授权属于同一个微信账号后，才取得资料并登录。微信自身是否再次显示授权页取决于微信的授权状态，本站始终先显示确认按钮。有有效登录时直接恢复账号，不重复跳转。退出后本次浏览器会话不立即自动登录，用户可点击“微信登录”重新授权。

两个阶段都要求在同一 AppID 的公众号配置 `tboxos.cn` 为网页授权域名；静默授权不能绕过 `redirect_uri` 域名校验。授权过程五分钟有效；刷新可以恢复资料授权提示，不能跳过身份校验或直接完成电脑登录、支付。

## 1. 发布这一版

1. 提交代码，运行 **后端部署（PM2）**，勾选 `start_services`。现有发布入口自动执行数据库预检、初始化/增量扩展并重启 API 和 worker。只上传包而不启动服务，不会更新正在运行的服务。
2. 运行 **前端与后台部署（OSS）**，选择 `app`。此次两阶段授权修改了后端和主站，管理后台不需要重新部署。
3. 填写下述微信平台与项目后台配置，然后用真实微信完成授权和一笔小额支付验收。

不用新建数据库、不用清库、不用手工跑 SQL。本版保留 `2026-10-23.2` 基线及已发布的扩展，通过 `schema_extensions` 自动新增 `wechat_login_authorizations`，保存两阶段授权作用域和 OpenID 哈希，随登录流程清理；重复部署不覆盖数据。原有微信配置、身份映射、登录流程、站内资料及支付链接保留。只做本地或手动部署时，执行现有 `pnpm db:init`。

无需新增 GitHub Secrets 或 `WECHAT_*` 环境变量。公众号及支付密钥在项目后台加密保存；继续保留并备份服务器 `shared/secrets/provider.key`，不能随部署重新生成。

## 2. 微信公众平台

使用**具有网页授权权限的已认证服务号**，取得对应的 AppID 和 AppSecret。在账号的接口权限中确认网页授权和获取用户资料可用。

| 配置 | 本项目填写内容 |
| --- | --- |
| 网页授权域名 | `tboxos.cn`，不带协议、路径或末尾 `/` |
| JS 接口安全域名 | `tboxos.cn`，用于 `wx.config` / `chooseWXPay` |
| 开发接口 IP 白名单 | API 服务器访问微信接口时的实际公网出口 IP；不是 GitHub runner IP，也不是 CDN IP |
| 登录授权回调地址 | 代码自动使用 `https://tboxos.cn/`，无需再填 API 域名作为登录回调 |

按微信控制台要求下载 `MP_verify_*.txt`，原文件名、原内容放入仓库 `app/public/`，提交后重新发布主前端。确认 `https://tboxos.cn/MP_verify_实际文件名.txt` 直接返回校验文字，不能是网站首页或跳转。

此方案的二维码是本站授权链接，统一使用上述服务号。不需要另申请微信开放平台“网站应用”，也不需要公众号消息服务器、消息 Token、EncodingAESKey 或关注事件回调。

## 3. 项目后台：微信登录

打开项目后台的 [微信登录](https://admin.tboxos.cn/#/wechat-login) 页面：

| 字段 | 填写内容 |
| --- | --- |
| 认证服务号 AppID | 上一步的服务号 AppID |
| 服务号 AppSecret | 同一服务号的 AppSecret，保存后加密，留空保留原值 |
| 前端网站根地址 | `https://tboxos.cn`，不带路径或 `#` |
| 开放微信登录 | 配置完成后勾选并保存 |

登录不依赖支付开关；只做微信登录时，到这里即可。首次微信资料授权自动建立个人账号和默认账本，没有单独注册步骤。每次 `snsapi_userinfo` 资料授权成功后，使用微信返回的昵称和头像替换站内资料；静默识别和恢复已有登录不会修改资料。用户仍可在账号设置修改昵称、上传 JPG/PNG/WebP 头像（不超过 2 MB），或恢复默认头像；下一次主动资料授权会重新同步微信资料。

扫码确认登录电脑时，服务端同时给电脑和扫码的手机各签发一个独立会话，两端进入同一个账号。手机自动保存自己的登录状态，无需再次授权；两端令牌互不相同、互不泄露，撤销一台设备不会退出另一台。仅扫码或拒绝确认不会为这次扫码签发会话；重复提交确认不会增加设备会话。

## 4. 微信支付商户平台

开通 **JSAPI 支付**，并绑定与“微信登录”一致的服务号 AppID。配置 **JSAPI 支付授权目录**：

```text
https://tboxos.cn/
```

末尾 `/` 必须保留，不填写 `/#/ai/recharge`。电脑端扫码网页和微信内购买均使用 JSAPI，这套桌面流程无需开通 Native。微信外手机浏览器直接购买还需开通 H5 并配置 H5 支付域名 `tboxos.cn`，不使用的渠道不勾选。网页支付无需配置移动应用 AppID。

只开通 JSAPI 时，微信外的手机浏览器也可以生成支付网页二维码或复制支付链接到微信打开；不会仅因手机宽度而禁用购买。若同时开通 H5，微信外手机浏览器优先使用 H5 直接唤起微信。扫码、复制链接仍执行同一套账号核对和单手机占用规则。

准备商户号、商户 API 证书序列号、配套商户 API 私钥、32 字节 API v3 密钥，以及当前商户使用的微信支付公钥 ID / 公钥 PEM（或平台证书序列号 / 平台证书 PEM）。商户私钥和微信支付公钥用途不同，不能互换。

参考：[JSAPI 开发指引](https://pay.wechatpay.cn/doc/v3/merchant/4012791870)、[支付授权目录](https://pay.wechatpay.cn/doc/v3/merchant/4013287088)。

## 5. 项目后台：微信支付与资源包

在项目后台的 [支付订单 → 微信支付配置](https://admin.tboxos.cn/#/payments) 填写商户及证书密钥信息，并设置：

| 字段 | 填写内容 |
| --- | --- |
| 服务号 AppID | 与“微信登录”一致 |
| 服务号 AppSecret | 自动复用“微信登录”中同 AppID 的密钥，无需重复填写 |
| API 公网地址 | `https://api.tboxos.cn`，不带 `/api/v1` |
| 支付网页地址 | `https://tboxos.cn` |
| 商品描述 | 例如 `T方舟 服务余额充值` |
| 微信内网页与电脑扫码网页 · JSAPI 支付 | 开通后勾选 |
| 开放新充值订单 | 全部配置完成后勾选 |

“开放新充值订单”是在线购买总开关，JSAPI 是支付渠道开关，两项需要同时启用。只勾 JSAPI 时，后台会明确提示总开关尚未开启，前端购买按钮保持禁用。开启总开关并保存后刷新购买页即可，无需重新部署。

再到 **资源包与费率** 发布需要售卖的资源包版本并上架；只有草稿不会出现在购买页。

服务端自动在支付请求中设置通知地址，不需要新增环境变量：

```text
支付通知：https://api.tboxos.cn/api/v1/payments/webhooks/wechat
退款通知：https://api.tboxos.cn/api/v1/payments/webhooks/wechat/refunds
```

两个地址必须公网 HTTPS 可达，Nginx/WAF 不得要求登录、拦截微信通知或改写请求体。API 需能访问 `api.weixin.qq.com`、`api.mch.weixin.qq.com`；用户微信需能加载官方 SDK `https://res.wx.qq.com/open/js/jweixin-1.6.0.js`。

微信内前端调用官方 JS-SDK `wx.config` 和 `wx.chooseWXPay`，服务端缓存并签发页面 JSAPI ticket 签名，登录取得的 OpenID 直接作为付款人。前端成功提示不能发放额度；服务端继续校验微信签名、商户、订单金额后幂等入账。

## 常见排查

- 不能登录：检查是否具备网页授权权限、AppID/AppSecret 是否属于同一服务号、网页授权域名及校验文件。
- SDK 初始化失败：检查 JS 接口安全域名、服务号接口权限、实际公网出口 IP 白名单，以及 API 到微信的网络。
- 不能调起支付：检查 JSAPI 产品开通、AppID 与商户绑定、带末尾 `/` 的支付授权目录、RSA 私钥和证书序列号。
- 已付款未显示到账：先在原订单刷新或后台“渠道核对”；检查微信通知是否送达，不要凭前端回调手工标记成功或反复创建订单。

本地验证使用模拟微信响应，不会真实授权或扣款。公众号和商户的最终可用性需在上述真实配置完成后，用真实微信和小额订单验收。

## 电脑扫码网页支付与代付

电脑端生成本站网页二维码（10 分钟内有效，且不超过原订单有效期），不会在电脑调用 `chooseWXPay`。用户在手机微信扫描后，每次重新通过微信 OAuth 核对当前微信身份，再由服务端查询原订单的受益账号。旧的本站登录缓存不能代替本次身份核对；核对结果绑定本次链接和新登录会话，五分钟内有效。链接只含 256 位随机凭据，不含登录 Token、OpenID、金额或可修改的收款账号。

付款扫码使用静默授权核对实际微信身份。已经通过该公众号登录过的用户直接继续付款，不重复弹出昵称头像授权；首次使用的微信身份仍需明确同意资料授权以创建账号。普通登录时的资料授权和昵称头像更新逻辑保持独立。

- 同一账号：自动生成 JSAPI 支付会话，并在微信网页调用 `chooseWXPay`。
- 不同账号：弹窗明确展示充值对象昵称、头像、账号尾号、商品和价格；用户点击“为 xxx 付款”后才请求微信支付。不确认或取消不会发起支付。身份按服务端用户 ID 核对，不能靠昵称是否相同判断。
- 额度接收人始终是原订单用户；代付人的 OpenID 只用于微信付款。发起后固定付款人，其他微信账号不能接管同一支付会话；需要更换付款人时，先核对原订单再重新下单。
- 链接参数在授权前及支付页进入时立即从地址清除，只在当前页面内存和必要的单次 OAuth 往返中保留。刷新或返回已处理的地址会显示说明，不自动再次调起支付。原手机在未刷新的页面可主动重试；需要更换手机时，在原设备先“核对支付结果”，确认未付款后“关闭订单”并重新下单。
- 第一台手机开始微信授权时，MySQL 事务锁定二维码对应的独立授权流程；即使第二台手机使用同一微信账号，也不能接管。付款发起后不会因授权超时而解锁给其他手机；微信商户订单号和额度入账仍保持幂等。
- 登录二维码和支付二维码通过 `/api/v1/qr/ws` 推送状态，浏览器不定时请求状态接口。电脑二维码盖层显示已扫码、等待手机确认、等待支付、取消、过期和支付成功；重连收到当前快照。手机取消会同步到电脑。服务端保留可信支付查询及跨进程状态恢复，弥补微信通知延迟；这不依赖浏览器轮询或 Redis。

支付进度集中显示在弹窗中，微信 SDK 成功返回后先显示“正在确认到账”，收到服务端已支付状态才显示成功。购买页不随之持续加载。历史订单详情显示剩余支付时间，“核对支付结果”和“关闭订单”是两个独立操作；移动端购买按钮固定在底部。此次无需新增环境变量或数据库迁移，发布后端、主站和管理端即可。

服务器继续使用 `/www/wwwroot/tbox/shared/api.env`，基本变量如下；填写真实值，不要覆盖已有正确配置：

```dotenv
PORT=6868
MYSQL_HOST=127.0.0.1:3306
MYSQL_USERNAME=t_box
MYSQL_PASSWORD='你的数据库密码'
MYSQL_DATABASE=t_box
OSS_ACCESS_KEY_ID='服务器业务文件上传账号的 AccessKey ID'
OSS_ACCESS_KEY_SECRET='对应的 AccessKey Secret'

# Redis 可选；不使用时 REDIS_ADDR 留空。使用时填写实际端口和密码。
REDIS_ADDR=127.0.0.1:3508
REDIS_PASSWORD='你的 Redis 密码，无密码时留空'
REDIS_DB=5
```

`HOST`、`NODE_ENV`、`TASK_WORKER_MODE`、OSS 地域/Bucket、应用域名以及前端 `VITE_API_BASE_URL` 沿用现有 Actions 自动配置；正常 PM2/OSS 发布不用手填。若主动限制 `CORS_ORIGINS`，必须包含 `https://tboxos.cn`，否则二维码 Socket 连接会被拒绝。Nginx 继续向 API 转发 WebSocket Upgrade，现有 `/api/` 通用转发即可覆盖新入口。

环境变量完整模板见 [PM2 配置](../deploy/pm2/api.env.example) 和 [API 高级配置](api-environment.md)。保留并备份 `shared/secrets/provider.key`；修改服务器环境后重新运行 PM2 部署并勾选 `start_services`，或使用现有发布脚本重新加载配置。
