# 应用本地资源、更新与启动诊断

## 安装与资源的边界

账号安装状态由 API 管理：安装版本、授权、后端生命周期。设备资源状态由宿主资源管理器管理：下载、校验、就绪、损坏修复。两者不能互相代替。应用市场分别展示“安装状态”和“本机资源”；浏览器清理缓存不会删除账号安装记录，重新打开会恢复资源。

资源包只包含公开的 HTML、JS、CSS、图标等静态文件，不保存登录 token、SDK 授权、API 响应或用户业务数据。本地资源可用不代表业务接口离线可用；后端登录有效性、权限、业务写入仍由服务器确认。

应用无需实现安装/下载代码。构建插件 `scripts/vite-offline.mjs` 自动生成 `tbox-resource.html`、资源安装器及 Service Worker。应用继续使用原来的 Web SDK，前后端工具协议不变。

## 离线启动与权限边界

### 网页游客模式

四个系统工具在应用自身的 `server/src/release.ts` 声明 `guestAccess: 'local'`。宿主构建插件从应用声明生成允许名单；新增应用不会因为添加一个路由就获得游客权限。原生随包能力另外由 `build.config.json` 声明。

- 网页无需登录即可进入 OS，使用计算器、单位换算、月历/农历/节气、世界时钟、秒表和时间换算。AI、记账、账号数据及云端日历事件/倒计时仍需登录；后端继续逐次校验安装、权限和账号。
- `/api/v1/app-market/local` 是无需认证的只读发布目录，只返回版本本身声明游客兼容、且已发布的系统 Web 应用；不创建账号安装、不执行后端生命周期、不返回用户资料、subject、grants 或 token。草稿、待审核版本、用户应用不能进入公开目录。新声明不会把依赖后端的旧版本自动变成游客版本。部署此功能后，需要通过原有应用发布流程发布支持游客的新版本。游客 SDK 仅开放本地运行、导航和隔离存储；前端工具名称仍保留用于 SDK 握手，不代表获得后端执行权限。
- 首次在线访问正式网页时，宿主 Service Worker 校验并保存页面资源，资源管理器后台保存四个工具的独立来源资源。公开目录另存于设备，不依赖登录记录。资源完整保存后，退出登录或断网刷新仍可进入桌面和打开工具；不同账号与游客的设备数据不混用。
- 已缓存目录先恢复，联网检查在后台进行。新版资源准备失败继续保留原版本；更新不会中断当前打开的页面。账号安装与更新仍由应用市场管理，游客基线不冒用账号安装。
- 离线能力要求 HTTPS（本机 localhost 也可）、浏览器支持 Service Worker 且未清理缓存。浏览器从未访问过的网站无法首次断网打开。Vite 开发页面依赖各应用开发服务，不属于离线发布包；正式部署必须确保工具产物来源与宿主分离、提供完整资源且版本已发布。

### 原生随包系统工具

计算器、单位换算、日历、时间在各自 `build.config.json` 声明 `native: { bundled: true, guest: true }`。应用自己声明是否参与，宿主不维护应用业务列表。只有默认安装的系统应用可以使用此能力；记账属于用户应用，继续通过应用市场安装。

`pnpm native:sync` 先使用 **`pnpm run pack`** 重新构建宿主和独立应用，再生成按摘要组织的原生资源及公开索引。不能写成 `pnpm pack`，后者是 pnpm 内置的 npm 压缩包发布命令，不会执行项目构建。

- Android 资源位于 APK 的 `assets/tbox-packages`，iOS 位于应用 Bundle 的 `tbox-packages`；均在 Capacitor `public` Web 根目录之外。宿主 Web 根目录只含公开的 `tbox-bundled-applications.json` 索引。
- 第一次启动，无账号、无网络也可以直接进入 OS 使用这些工具。原生插件从签名包读取资源，复用同一套摘要校验和原子导入逻辑，再通过应用独立的 loopback 来源打开；不会访问索引中的占位网络域名。
- 清单使用可打包的 `tbox-package-files.json` 名称。构建拒绝隐藏资源路径，避免 Android AAPT 静默丢弃文件后，安装包看起来构建成功却无法首次打开。
- 游客不是一个伪造的登录账号，`identity.user` 仍为空。SDK 只开放本地计算、导航和设备存储；云端 API、文件、提醒等操作明确要求登录/联网。游客记录与登录账号隔离，不自动合并。
- 登录后的已安装版本如已在本机准备完成，优先使用该版本；资源尚未就绪时仍可打开随包基线。随包基线不能冒用后端安装版本和授权。应用市场仍负责后续版本的下载、校验和安装激活，后台预取不会把未安装的新版本直接切换到运行中页面。
- 原生 `has` 会按需导入匹配摘要的随包资源，因此市场版本与随包版本字节相同时也不会重复下载。更新、修复不删除签名包中的基线副本。

只有缓存静态文件还不够：宿主恢复账号、展示桌面、生成运行描述和连接 SDK 都不能成为本地计算的联网前置条件。

- 登录成功后保存最小账号展示资料；再次启动先恢复本地界面，并在联网时后台验证 `/auth/me`。`identity.verification = local` 只表示设备上的账号界面，不代表账号有效。没有历史登录资料仍可使用游客本地工具；访问账号功能需要联网登录。
- `/app-market` 为有效安装附带 `localBinding`，只包含应用隔离的 subject 与本机存储开关，不附带 bearer、密码、解锁 token 或后端授权票据。目录同步后即可准备所有已安装资源，不要求逐个打开应用。
- 宿主按账号保存已安装目录与实际安装版本，按账号/设备类型保存桌面显示顺序。本地启动使用安装版本，不会把已发布但未安装的新版当作当前版本。
- `localLaunch.ts` 是统一策略边界。`runtime.context` 返回 `access: local`，后端权限数组为空；只允许本地上下文、基础会话状态、导航和明确允许的设备存储。数学、单位、日期等纯函数由应用直接运行，无需 SDK 请求。
- `api.request/invoke`、文件读写、资源绑定、提醒同步、事件订阅、安装更新和 AI 前端工具执行仍需联网。前端工具执行继续获取服务器运行描述；其他后端操作继续验证实际安装、版本、账号及权限，不能用缓存授权。断网时立即返回 `NETWORK_REQUIRED`，不排队写入、不伪装成功。
- 断网恢复后重新验证账号并同步目录。已撤销的会话会清除账号和目录快照；安装被撤销或版本变化会关闭旧 SDK 通道。账号切换不会复用其他账号的快照或本机应用存储。

| 离线可用（资源已准备） | 需要联网 |
| --- | --- |
| 计算器全部本地数学计算、单位换算、本机历史与收藏 | AI 对话和工具任务、账单读写、支付与账号操作 |
| 月历、农历、节气、日期计算 | 日历事件和单次状态、官方调休数据更新（已缓存安排可查看） |
| 世界时钟、时区与时间换算、秒表 | 服务端时间校准、持久倒计时的创建/控制/删除、提醒同步 |

网页版需要先在线使用正式构建，让宿主和应用资源完成缓存；系统回收/用户清理缓存后必须重新联网下载。原生随包系统工具首次使用无需下载或登录，其他独立应用仍须先在该设备下载完成。缺失资源或禁用浏览器存储时明确提示联网。Vite 开发地址用于热更新，不承诺断网刷新可用。

宿主页面联网优先更新，但网络请求超过 2 秒或失败时使用已验证的静态缓存，避免弱网络把冷启动一直挂住。缓存只拦截构建清单中的静态路径，API 不进入 Service Worker 缓存。

启动页显示读取启动信息、校验本地资源、加载页面、连接 SDK 的实际阶段；等待超过五秒显示已等待时间，真实下载另显示文件数量。开发模式通过同源 Vite 诊断接口检查应用自己的服务是否启动，目标来自仓库构建声明，不接受请求指定地址，也不向应用来源转发账号凭据。应使用 `pnpm dev` 或 `pnpm dev:apps` 启动独立应用；只启动宿主的 5173 不会自动提供单位换算的 5180 服务。

## 下载和原子切换

1. 使用后台发布的不可变地址 `/<appId>/<artifact-digest>/`。
2. 下载 `artifact.json`，核对应用标识、协议、文件清单摘要与发布记录。
3. 逐文件校验 SHA-256；限制 2000 个文件、单文件 5 MiB、合计 20 MiB，拒绝跳转、路径穿越和多余私密请求头。
4. 所有文件成功后，写入完成标记并启用资源。失败时删除暂存资源，保留其他版本。
5. 前端点击安装/更新，先准备目标版本资源，再调用后端安装生命周期。默认安装的系统应用，以及其他设备安装的应用，在目录同步后自动准备当前安装版本。

网页在应用自己的来源中操作 Cache Storage 和 Service Worker，宿主通过一次性随机标识、来源和窗口绑定接收准备进度。完整包缓存的完成标记写入最后，未完成的缓存不能作为本地版本启动。不可变应用页面采用缓存优先；宿主本身的可变地址继续联网更新。

Android/iOS 通过 `capacitor-app-resources` 插件下载到私有持久目录，临时目录下载完成后使用同一文件系统中的重命名切换。原生 HTTP 服务只监听 `127.0.0.1`，每个应用/版本使用独立端口和随机路径，只提供清单中的静态文件；每次读取还会校验文件摘要。它不提供 API、目录列表、写文件接口或宽泛 CORS。应用与 Capacitor 宿主依然不同源，所有权限仍通过 SDK 检查。

Android 正式包只为 localhost/127.0.0.1 开放明文连接，远程应用资源下载仍必须 HTTPS。iOS 正式包只允许本地网络例外，不开放任意远程 HTTP。资源目录不参与系统云备份。

## 更新与回退

既有应用目录 WebSocket、前台恢复和断线轮询负责发现新版本。宿主静默准备已安装版本与已发布更新，五分钟内避免重复预取；下载失败采用 30 秒起、最长 5 分钟的退避，用户主动重试不受后台退避影响，隔离版本不在后台重复尝试；准备更新不会变更后端安装状态，也不会中途替换正在运行的 iframe。用户仍通过现有更新提示或应用市场确认安装。

只有应用真正完成 SDK ready 握手后，才记录为当前用户的可用版本。每个用户/应用保留上次可用版本；资源层保留当前、前一个可用版本及最近准备的更新包，过旧资源在成功启动后清理。公开资源可以跨账号复用，可用版本记录按不透明 subject 隔离。

下载失败不会提交后端更新。启动失败且有旧可用版本时，宿主请求 `/applications/:id/rollback`。后端在事务和安装锁中检查：

- 当前安装版本仍是这次失败的版本，没有其他安装任务。
- 目标属于本应用，且该用户曾成功安装它。
- 目标为当前发布版本或因正常更新而退役的不可变历史版本，不能是草稿或待发布版本；权限是当前已授权权限的子集。
- 使用正常后端生命周期切换，不能只把旧页面与新版授权拼在一起。

回退成功后重新获取运行描述，再打开旧版本，失败版本进入本机隔离列表，防止自动重试循环。无法安全回退时显示错误，可“重新打开”或“修复资源”。修复只清理当前静态包，不清除应用业务数据。后端生命周期未确认时不会伪装回退成功。

## 启动耗时

宿主记录 `resolving`、`preparing`、`loading`、`connecting`、`rollback` 的实际耗时、总耗时、平台、版本、资源来源和结果。动画进度不参与计时；下载时另显示真实文件完成数量。

本机最近 100 条记录位于 `localStorage['tbox.application-launches.v1']`，并发出 `tbox:application-launch` 事件。宿主以认证 POST `/applications/:id/launches` 上报受限结构，API 写入 `applicationLaunch` 结构化日志，由 PM2/Docker 日志保留。记录不含用户消息、文件 URL、应用输入、凭据或 SDK 响应。浏览器计时仅作诊断，不能作为计费或权限依据；离线未成功上报的记录仍留在本机，不阻塞应用启动。

## 使用条件与发布

本次独立应用补丁版本：计算器、日历、时间 `1.1.2`；记账 `1.1.3`；单位换算 `1.0.1`。Actions 继续从各自 manifest 读取版本，提交后由后台管理手动发布。

- `pnpm dev` 的 Vite 地址使用开发模式，跳过不可变资源安装，保留热更新。
- 正式网页版需要 HTTPS（localhost 开发验证除外）。推荐宿主和资源使用同一主域的不同子域，如 `os.example.com` 与 `apps.example.com`，避免浏览器的跨站存储限制。资源地址依然必须不同源。
- 禁用 Service Worker/存储、配额不足或旧构建缺少安装器时，网页版明确显示“在线加载”，不会把它标记成本地就绪。浏览器缓存无法承诺永久不被系统回收，回收后会重新准备。
- 原生端使用持久私有文件，不依赖 WebView 是否支持 Service Worker；开发热更新继续使用远程 Vite 地址。
- 现有旧版应用需要重新构建并发布一个新版本，才能在网页版使用新的资源安装器。旧产物保持不可变，不得覆盖旧版本目录。Android/iOS 可以校验并缓存既有符合 artifact 协议的静态包。
- 原生宿主新增了插件，必须运行 `pnpm native:sync` 并重新打包宿主。只更新网页或应用产物不会给已发行的旧原生宿主补上插件。

验证命令：`node --test scripts/application-resources.test.mjs scripts/operations-offline.test.mjs`、`pnpm test:ui-components`、`pnpm test:native`。`offline-host.test.ts` 执行真实宿主传输层，覆盖零 HTTP 的离线启动/存储、联网操作拒绝、重连授权和 401 失效；`local-launch.test.ts` 覆盖安装版本、跨平台、账号隔离与快照清理。原生文件/HTTP 验收分别使用实际 Swift 和 JVM 执行；不具备对应编译环境的平台会明确跳过该项。发行前仍须使用真实域名、设备和系统版本验证 WebView/系统网络行为。
