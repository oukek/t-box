# T方舟采集插件

版本 0.3.5。仅在 `https://www.dianxiaomi.com/*` 显示页内采集箱，读取用户已登录的店小秘采集列表。原平台页面识别、商品卡片按钮、平台详情抓取、平台适配目录及参考插件分析文件已移除。商品的来源平台名称和原链接属于返回资料，仍在预览/导出中保留，不据此访问商品详情。

## 安装与使用

```sh
pnpm install
pnpm --filter @t-box/product-collector check
pnpm --filter @t-box/product-collector run pack
```

安装包：`output/collector-releases/tark-collector-0.3.5.zip`。解压后，在 Chrome 扩展管理中打开开发者模式并加载解压目录；开发时可直接加载 `extensions/product-collector/dist`。更新插件后刷新原网页。未发布 Chrome Web Store。

1. 登录店小秘，进入采集箱页面，点击右下角“T方舟 · 采集箱”。
2. 点击“读取此页”。支持按名称搜索、20/50/100 条分页、上一页/下一页、指定页码和从当前页连续导入。
3. 连续导入顺序请求，每页成功后保存；停止在当前页结束后生效。遇到错误或空间上限即停止，之前成功导入的商品保留。
4. 在预览中筛选、多选，打开详情弹窗核对资料、图片、视频链接、规格价格、属性和包装，导出全部或选中商品。
5. 移除只清理插件临时预览，不修改店小秘记录。

商品仅存在 `chrome.storage.session`，关闭浏览器/重载扩展后不保留。最多 200 件、约 7 MB；超过容量时整页导入失败，不部分覆盖该页、不静默淘汰已有商品。导出格式 `tark.collector.products` v1；媒体是来源链接，不包含文件二进制。账号已接方舟后端；商品仍未上传。

## 请求与字段

后台通过 `chrome.scripting.executeScript` 在来源店小秘标签页的 MAIN world 执行 `POST /api/crawl/list.json`。请求体使用 `URLSearchParams`，保留 pageNo、pageSize、site=all、searchValue、productSearchType=name 及用户示例中的空筛选字段。不手动复制 headers；浏览器设置表单 Content-Type 和当前会话 Cookie，`credentials: include`。不新开标签页，也不读取或导出 Cookie。

响应必须 `code === 0`，包含有效 `data.page.list` 和匹配的分页信息。登录 HTML、业务错误、网络失败及分页异常均报错。失败状态商品跳过并说明；嵌套 JSON 格式错误标注缺失，其他字段仍可预览。

- 标题 name；原文描述 description/detail；详情 HTML 仅通过隔离 DOMParser 提取文本、图片，不在 UI 执行或直接渲染 HTML。
- 主图 imgUrl/previewImgUrl、详情图、规格图、视频、尺码表、说明文件分别标记来源。
- variant、attribute、packageInfo 等 JSON 字符串单独解析。规格保留选项、ID、价格、库存、图片；原始规格尺寸重量保留在商品结构数据中。
- 优先 sourcePrice + sourceCurrency、sourceDiscountPrice；缺少来源价格时使用 price + currency，币种缺失不猜测。sourcePriceUsd 等原值保留用于核对。
- 记录 ID 优先 idStr，拒绝不安全整数作为唯一标识。去重键优先来源平台 + productId，无来源编号时用店小秘记录 ID。重复读取更新已有商品，同页重复也只保留一份。
- 包装数值保留原值，不猜测接口未声明的单位。资料齐全仍标记“待核对”。

原始商品结构采用字段白名单，不保留 puid、createId、createName、updateId、updateName、权限、账户信息等业务元数据。接口样例原文件不打包、不提交。

## 架构与权限

```text
src/dianxiaomi/  请求参数、站点范围、列表响应解析与字段映射
src/extension/  页内入口、请求调度、隔离 HTML 解析
src/core/       商品类型、会话合并去重、导出
src/ui/         预览工作台与商品详情弹窗
```

权限为 scripting、storage、offscreen，以及店小秘、`https://tboxos.cn/*`、`https://api.tboxos.cn/*`。主站内容脚本只桥接经过服务端核验的账号摘要；外部通信仅允许方舟主站且核对授权窗口标签页、顶层 frame 和随机 nonce。采集界面可嵌入资源仍只允许店小秘。媒体预览会加载商品响应中给出的图片地址。

## 格式化与验证

复用根目录 `@antfu/eslint-config`；不另用 Prettier。构建不压缩 JS/CSS。

```sh
pnpm --filter @t-box/product-collector format
pnpm --filter @t-box/product-collector check
```

测试覆盖嵌套规格、来源币种、零值、安全整数 ID、图片和属性、去重更新、分页与失败响应、域名边界、敏感字段排除、容量原子性。真实店小秘接口仍受用户登录和服务端状态影响；模拟响应测试不代表登录会话下的线上接口已经验收。


0.3.0 验证记录：7 项单元测试通过；独立 Chromium 加载扩展，以用户提供的三件商品响应模拟接口，验证首次导入三件、规格分别 2/75/1 条、重复及跨页更新仍三件、详情弹窗、名称参数、连续翻页、停止、错误后保留、JSON 导出、390px 布局无横向溢出，以及其他站点不注入。请求检查确认 POST、自动表单 Content-Type、测试会话 Cookie 和无新增标签页。未使用用户真实登录会话调用线上接口。


## 0.3.1 商品页式预览

商品详情改为桌面左右布局：左侧主图与缩略图，右侧标题、来源价格、库存和规格选择。规格支持价格/库存/图片联动，多规格默认显示前八项，可搜索或展开。下方连续展示商品参数与详情图，保留全部规格表、媒体来源链接、采集检查及结构化数据折叠区。未获取的价格和库存不以商品汇总值替代。移动端采用全屏纵向布局，标题与关闭/导出操作固定可用。

7 项回归测试、格式检查、类型检查和构建通过。独立 Chromium 使用样例响应验证：11 张详情图连续展示、规格价格/库存/图片联动及清除选择、缩略图切换、内容导航、75 条规格展开与搜索、390px 下无横向溢出且底部操作可见、Esc 关闭。

## 0.3.2 插件账号登录

采集箱顶栏点击“登录方舟”，在账号弹窗选择同浏览器账号或微信扫码登录其他账号。已打开的新版方舟主站页面支持候选账号识别；没有打开主站时，登录按钮打开独立主站授权窗口，识别该 Chrome 用户配置保存的登录态。扫码不会切换电脑主站账号。已登录账号支持切换、恢复校验和退出；退出失败会保留登录态供重试。切换失败保留原账号，切换成功后尝试撤销原插件会话。

插件使用独立 7 天设备会话，凭据保存在限制为 trusted contexts 的 chrome.storage.local，由后台请求 API；商品和账号独立存储。未登录仍能读取/导出商品，登录不上传、不认领、不持久化商品。关闭浏览器仍清空商品临时预览。

授权复用五分钟微信 QR 流程及事务锁，无新增数据库表或外键。主站使用已验证账号批准插件专用流程；扫码状态通过现有 WebSocket 推送。插件流程的 poll / Socket 不返回登录令牌，只有持有随机 proof 的一次性 redeem 接口返回新会话。关闭未领取授权窗口会取消流程并撤销已签发但未领取的会话。

发布需要同时部署 API 和主站，再安装新版插件（刷新已打开的主站与店小秘页面）。正式域名固定为 tboxos.cn / api.tboxos.cn；未发布新版主站/API 时不能使用登录功能。不需要固定扩展 ID，插件启动授权时携带实际 runtime.id，服务端不依赖扩展 ID。

本地验证：8 项插件测试、5 项后端授权测试通过；插件、主站、API 类型检查通过，主站和插件生产构建通过。Playwright 使用模拟账号验证快捷登录成功、切换扫码、主站凭据保持不变，以及 390px 账号底部弹层和二维码页面无横向溢出。后端授权测试使用内存仓储替身，不代表真实数据库并发或微信扫码联调已验收；发布后还需真实账号验收。

## 0.3.3 Mac 版快捷登录

登录按钮打开的官方授权窗口可以识别本机 Mac 版已登录账号，点击后为插件签发独立会话。首次需允许浏览器访问本机应用；Mac 需运行且登录有效。支持 Mac 版密码与微信账号，微信扫码配置不可用时也可使用。插件无需新增站点权限，主站账号不会被切换，原商品采集行为不变。

需要一起更新后端、主站、Mac 核心/界面及插件。详见[Mac 快捷登录部署与验证](../../docs/mac-quick-login.md)。

## 0.3.4 登录展示调整

默认显示二维码，未识别到 Mac 不显示检测或连接失败提示。识别成功后显示头像、昵称和快捷登录，并收起二维码；选择其他账号返回扫码。Mac 登录失败后的扫码回退重新创建二维码，并拒绝旧 Mac 授权回调。首次需要浏览器授权时保留“使用 Mac 账号”入口。普通用户账号密码入口已隐藏。

## 0.3.5 账号优先级与活跃续期

本次配套主界面 `1.3.4`、Mac 核心 `1.0.4` 和同提交 API，先发布后端，再统一发布网页/Mac，最后分发插件。完整步骤见[发布顺序](../../docs/mac-quick-login.md#发布顺序)。

默认依次检测 Mac、同浏览器账号，均不可用时保留二维码。明确选择其他账号后不再自动切换。插件及网页会话为 7 天滚动有效期，PWA 与 Mac 为 30 天；服务端有效认证请求触发续期，最多每 5 分钟写入一次，过期会话不能续期。
